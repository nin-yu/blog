# Mission: 学会"设计 agent 系统"，用于 SGRT 标定/故障排查/日常 QA

## Why
我是利纳特(Linatech)放疗表面追踪(SGRT)工程师（熟悉自身系统：相机随加速器机架转动、标定板固定±30°、外参 X/轴/δ 求解、床板 QA 2mm/1°、ICP 胸腹表面配准等）。但**我在 agent 领域是小白**——只拿它写过代码，不懂得怎么"设计"一个 agent 系统。我要学会设计方法，然后用于自己手头的 SGRT 环节：标定引导 / 自动标定、故障排查、日常 QA。

## Success looks like
- 面对 SGRT 的一个环节，我**能自己判断该用 workflow 还是 agent**，不再是一团模糊。
- 我能为一个 SGRT 流程（先挑最容易的：标定 QA 或日常 QA）**亲手设计并搭出一个最小可用的 agent/workflow**，跑通并产出可复现结果。
- 我能讲清自己这个系统里：哪里该固定管线（workflow）、哪里该让 LLM 判断（agent）、需要哪些工具/记忆/检索。
- 能把故障排查做成"会查日志/文档、会拟定排查步骤"的智能助手，而不是靠人肉翻记录。
- 每学一块，我都能当场套到自己的一个环节上，而不是只会"认识名词"。

## Constraints
- 基础定位：**agent 设计零基础**（只用过代码生成）。一切从小白能懂的高度讲起，不跳步。
- 中文讲解；先概念/原理、再细节、直接给结论；默认不用类比（明确要求费曼讲法时才用直觉类比）。
- 数值一律给大白话含义 + 对工程的实质影响（精度/速度/成本）。
- 每次只讲一小块，配自测（判断/选择，附答案与解析），用真实 SGRT 场景当例子。
- 用高质量一手资料（见 RESOURCES.md），不靠二手口碑知识。
- 业余时间推进，内容精炼不冗长。

## Out of scope
- 不追求生产级安全审计/形式化验证；不做通用 agent 产品商业化。
- 不钻 GRPO/RL 数学细节（工程理解即可）；不追 LLM 训练端。
- 暂时不学多智能体协作、主动式智能体等进阶方向——先把"单 agent + workflow"设计学会。
