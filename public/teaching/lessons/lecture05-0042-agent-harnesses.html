Agent Harness：没有唯一正确，只有不同取舍

第 42 课（Lecture05 第 4 课）· 来源：lecture05.pdf p78-89 · 本课成果：理解"harness 是什么"、四个开源 harness（Mini SWE-Agent / OpenHands / Pi / OpenClaw）在工具/历史/权限/记忆上的不同取舍，以及"同一模型换个 harness 差别很大"

先给结论

Agent Harness = 包裹模型的"外壳/脚手架"——负责工具、记忆、上下文管理、执行等设计选择（p80-81）。不同 harness 做不同取舍：Mini SWE-Agent（只有 bash、线性历史）、OpenHands（事件溯源、持久终端）、Pi（4 个工具、树状历史）、OpenClaw（定时自唤醒、常驻 Gateway、Markdown 记忆）。

关键结论（p86-89）：同一模型，换个 harness 表现差别很大；没有"一种"正确搭法。

什么是 Agent Harness（p80-81）

Harness 把"模型"包成一个可运行的 agent。搭一个 agent 涉及的设计选择（p81）：工具、记忆、上下文管理、执行方式。不同 harness 为各自的任务与运行环境做不同取舍。

四个开源 Harness 的取舍（p82-85）

Harness工具历史执行/权限其他
Mini SWE-Agent 除 bash 外没有别的工具 完全线性：每步只 append 到 messages 用 subprocess.run 执行，每个动作完全独立（不保留有状态的 shell 会话） 极简
OpenHands — 每步存成事件（磁盘上每事件一个 JSON），每步从事件重建发给模型的消息 保持持久终端（tmux 会话，cd/环境变量等延续） 事件溯源
Pi Agent 只有 4 个：read / write / edit / bash，系统提示 < 1000 token 树状存储历史（可回到早期消息并从那分支） 没有权限系统——用启动时的权限运行 刻意简单：无 plan 模式、无 sub-agent 工具
OpenClaw — 每晚 3 点后台任务读当天笔记，把值得留的移入 MEMORY.md 作为常驻 Gateway运行（单进程拥有所有聊天通道） 每 30 分钟自唤醒（心跳回合，回 NO_REPLY 保持安静）；身份来自 Markdown 文件（AGENTS.md/SOUL.md/IDENTITY.md/USER.md/MEMORY.md 注入 system prompt）

Harness 影响有多大（p86-89）

  • p86 引用"coding-agents-harness-tax"：harness 会带来很大差别。
  • p87-88 提到 Meta-Harness（自动设计/优化 harness 的方向）。
  • p89 结论："没有唯一正确的搭法。本课程你会亲自实验这些设计决策——说不定你能造出下一个流行的 agent harness :D"。

四种"设计维度"抽出来看

维度极端 A极端 B
工具数极少（Pi：4 个）通用（bash 全能，Mini SWE-Agent）
历史结构线性追加（Mini SWE-Agent）树状可分支（Pi）
状态持久无状态（Mini SWE-Agent subprocess）持久会话（OpenHands tmux）
自主节奏被动（等用户）主动心跳（OpenClaw 每 30 分钟）
权限无（Pi，随启动权限）有权限系统

对你 SGRT 系统的含义

  1. 你的排查 agent 也在做这些取舍：工具给几个？历史线性还是可回溯？要不要持久会话？要不要权限系统（医疗场景必须要有）？
  2. 医疗场景不能学 Pi 的"无权限系统"：Pi 刻意简单、随启动权限运行——这在你的设备控制场景是危险默认，必须显式权限 + 人审。
  3. OpenHands 的事件溯源值得借鉴：每步存事件、可重建消息——天然满足"可审计"（医疗合规要能复盘每步）。
  4. OpenClaw 的"夜间整理记忆"思路：定期把当天要点沉淀进长期记忆，适合你积累"故障处置经验库"。

自测（先答再展开）

Q1. Agent Harness 是什么？它涉及哪些设计选择？

展开答案

包裹模型的外壳/脚手架。涉及工具、记忆、上下文管理、执行方式等设计选择；不同 harness 为各自任务做不同取舍。

Q2. Pi Agent 和 Mini SWE-Agent 在工具与历史上各有什么取舍？

展开答案

Pi：只有 4 个工具（read/write/edit/bash）、历史树状可分支、无权限系统、刻意简单；Mini SWE-Agent：除 bash 无其他工具、历史完全线性、用 subprocess 无状态执行。

Q3. OpenHands 的"事件溯源"和 OpenClaw 的"夜间整理记忆"各解决什么？

展开答案

OpenHands：每步存为事件、可从事件重建消息，便于审计/复现；OpenClaw：每晚把当天笔记里值得留的移入 MEMORY.md，长期沉淀记忆。

Q4. 你的医疗场景排查 agent，哪两个 harness 的做法不能照搬、哪两个可借鉴？

展开答案

不能照搬：Pi 的"无权限系统"（医疗必须显式权限+人审）。可借鉴：OpenHands 的事件溯源（可审计）与 OpenClaw 的记忆沉淀（积累经验库）。
