标准接口三代：从"改模型"到"改描述"

第 34 课（Lecture04 第 4 课）· 来源：lecture04.pdf p47-50 + MCP 规范 · 本课成果：理解标准接口的核心转向，掌握 REST / 函数调用 / MCP 三代的差别，以及函数调用 JSON schema 长什么样

先给结论

前面 Toolformer/Gorilla 是"改模型去适配工具"——每加一个 API 就得再训一次。标准接口转向相反方向：把工具描述标准化，让任何模型都能用（运行时给 schema，而不是训练时灌进去）。

三代（p48）：REST API（面向人：端点+文档，无机器可读契约）→ 函数调用 Function Calling（面向模型：每个工具一个 JSON schema，模型输出 name+args，harness 校验并分发）→ MCP（面向生态：一个协议任何客户端，服务端暴露 tools/resources/prompts，运行时发现，写一次跨宿主复用）。

核心转向（p47）

思路做法问题
改模型去适配工具Toolformer/ToolkenGPT/Gorilla：每个新 API 都要再训一次不可扩展
改工具描述让任何模型能用REST/函数调用/MCP：运行时给 schema，而非训练时✅ 可复用

第一代：REST API（p49）

GET https://api.weather.com/v1/current?city=Stanford
→ 200 {"temp_f": 74, "conditions": "sunny"}

GET 读取   POST 创建   PUT 更新   DELETE 删除

局限：模型必须知道 URL、参数名和返回结构——这些藏在文档里，没有机器可读的契约，模型得"读文档 + 手写请求"。

第二代：函数调用 Function Calling（p50）

把工具描述成 JSON schema，模型只负责输出"名字 + 参数"，由宿主程序校验并真正执行。

Tool Schema（给模型看）:
{ "name": "get_weather",
  "description": "Current weather",
  "parameters": { "type": "object",
    "properties": { "city": {"type": "string"} },
    "required": ["city"] } }

Model Output（模型产出）:
{ "name": "get_weather", "arguments": {"city": "SF"} }

关键改进：schema 活在代码库里，模型输出结构化的 name+args，由 harness 校验分发——不再靠模型手写 HTTP 请求。

第三代：MCP（p51-56 + 规范）

面向生态：一个协议，任何客户端。服务端暴露 tools/resources/prompts，客户端运行时发现，写一次跨多个宿主（host）复用。

REST API函数调用MCP
面向人模型生态
契约文档（非机器可读）每工具一个 JSON schema一个协议 + 运行时发现
模型做什么读文档、手写请求输出 name + argstools/list → tools/call
复用性每个服务单独对接schema 在代码库写一次，跨宿主复用

MCP 一句话定位（规范原文）

MCP 是一个开放协议，让 LLM 应用与外部数据源和工具无缝集成。它用 JSON-RPC 2.0 在 Host（发起连接的 LLM 应用）、Client（宿主内的连接器）、Server（提供上下文与能力的服务）之间通信。设计灵感来自 LSP（语言服务器协议）——LSP 标准化了"如何给整个开发生态加语言支持"，MCP 标准化"如何给 AI 应用生态加工具与上下文"。

对你 SGRT 系统的含义

  1. 优先做"函数调用式"工具：把你设备 API 包成带 JSON schema 的工具，模型只产 name+args，由你的 harness 校验——比让模型手写 HTTP 稳得多。
  2. MCP 的价值在"复用"：若你希望同一套 SGRT 工具被多个宿主（IDE、聊天界面、自研 agent）共用，MCP 一次性封装最省事。
  3. schema 是契约：参数名、类型、必填项要写清（防呆），这决定模型调得对不对。

自测（先答再展开）

Q1. 标准接口的"核心转向"是什么？

展开答案

从"改模型去适配工具"（每个新 API 都要再训练）转向"把工具描述标准化，让任何模型都能用"（运行时给 schema，而非训练时）。

Q2. REST API 作为工具接口的局限是什么？

展开答案

模型必须知道 URL、参数名和返回结构，而这些只存在文档里、没有机器可读契约，模型得读文档并手写请求。

Q3. 函数调用比 REST 强在哪？"harness"做了什么？

展开答案

把工具描述成 JSON schema，模型只输出 name+args；由 harness（宿主程序）校验参数并真正分发执行。模型不再手写 HTTP 请求，schema 活在代码库里、可校验。

Q4. 你的 SGRT 工具体系，什么时候值得上 MCP？

展开答案

当你希望同一套工具被多个宿主（IDE、聊天界面、自研 agent）复用时——写一次 MCP server 跨宿主复用。若只有单一宿主，函数调用式 schema 就够。
