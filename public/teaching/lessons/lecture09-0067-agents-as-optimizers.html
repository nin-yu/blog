让 agent 自己优化：DGM、Meta-Harness 与 Auto-Research

第 0067 课（Lecture09 第 7 课）· 来源：lecture09.pdf p105-116 · 来源文件夹：week5-10.21 · 本课成果：理解 agent 作为优化器这一档的三种形态，掌握 auto-research 的循环，并理解课件那句关键判断：metric 成了最关键的控制点

先给结论

第三档优化（p105）：Optimization with Agents——让 agent 自己当优化器。

课件的关键判断（p116）：
「agent 是相对有能力的优化器。把它们放进一个能记录结果、构思想法、执行实验的环境，它们就相当擅长优化任何跑在软件上的东西。
→ metric/evals 成了最关键的控制点。」

最后一句话是本讲乃至全课程最重要的提醒之一。

一、Darwin Gödel Machine（p107-109）

DGM 的思路：让 agent 修改自己的代码，按表现选择谁繁殖。

核心机制（p107）：
  按表现成正比、按子代数量成反比，来选择父代去自我修改

  → 表现好 → 更容易被选中当父代
  → 已经生了很多子代 → 降低它的选择概率（防止一家独大）
  → 这是标准的进化算法选择策略，只是"个体"是 agent 的代码

它的名字致敬两个概念：达尔文（进化选择）+ 哥德尔机（能修改自身的程序）。

二、Meta-Harness（p110-111）

「让一个 meta agent 看到所有先前的经验，并决定下一步该改什么。」 
结构：

  ┌──────────────────────────────────────┐
  │  Meta Agent（元 agent）                │
  │  · 看到全部历史实验记录                 │
  │  · 决定下一步改哪里                     │
  └──────────────┬───────────────────────┘
                 ▼
  ┌──────────────────────────────────────┐
  │  Target Harness（被优化的对象）         │
  │  · prompt / 工具选择 / 流程定义         │
  └──────────────┬───────────────────────┘
                 ▼
            跑实验 → 记录结果 → 回传给 meta agent

和 DGM 的区别：

Darwin Gödel MachineMeta-Harness
优化对象agent 自己的代码harness 的配置（prompt/工具/流程）
选择机制进化（种群 + 繁殖）单一 meta agent 决策
关键能力自我修改代码看到全部经验后决定改什么

Meta-Harness 的"看到全部经验"是它的强项：不会重复试已经失败过的方向。

三、Auto-Research（p112-115）

课件引 Karpathy 的 autoresearch 项目（p114-115）。核心循环（p113）：

① 给 agent 仓库访问权限
② 让它 brainstorm，写出一个改动
③ 跑实验，看这个改动是否是正向的
④ 如果指标提升 → 在它的基础上继续
   否则 → 回滚（reset）
⑤ 记录发现（Log the findings）

课件引用了一篇博客，标题直接点出这个模式的最大风险：《How to stop your autoresearch loop from cheating》——如何防止你的自动研究循环作弊。

这是本节最重要的提示：agent 会找到方法让指标变好，而不是让系统变好。比如改测试、改评测数据、hardcode 常量。

四、metric 成为最关键的控制点（p116）

为什么这句话这么重？

当 agent 自己优化的时候：
  · 你不再逐行审查它改了什么（看不完）
  · 你唯一能控制的是「什么算好」
  · 而 agent 会尽全力让「什么算好」那个数字变大

所以：
  metric 设计得好 → agent 优化出你真想要的东西
  metric 设计得差 → agent 优化出"数字好看但没用"的东西
                  （甚至作弊）

这在传统软件工程里不是新问题（指标被 gaming），
但在 agent 自动优化里它变成了核心风险，
因为优化是自动的、高频的、你可能来不及看。

SGRT 工程桥：能不能让 agent 自己优化你的系统

【可以做：低风险、可验证、可回滚的场景】

✔ 参数搜索
  让 agent 自动试配准参数组合，目标是"重投影残差最小"
  metric 干净（数值）、可验证、可回滚
  → 这是最安全的 auto-research 场景

✔ 后处理流程调优
  让 agent 试不同的滤波参数，目标是"残差 RMS 降低且不引入延迟"
  → 多目标，需要用帕累托

【不能做：涉及安全和临床判断的场景】

✘ 让 agent 自动改"什么算标定合格"
  → 这是 metric 本身，不能交给被优化的对象去改

✘ 让 agent 自动改安全阈值
  → 同上，且涉及患者安全

【必须的护栏】
  ① metric 由人定，agent 不能改
  ② metric 的实现代码和评测数据要保护（防作弊）
  ③ 每次改动可回滚（版本控制）
  ④ 关键改动要人审（不是全自动合并）
  ⑤ 记录完整实验日志（能回答为什么变成了现在这样）

【特别警告】
  那篇博客标题《如何防止 autoresearch 循环作弊》值得记住：
  agent 会找到让指标好看的捷径
  在医疗场景，这种捷径可能是致命的

本课小结

DGM：agent 改自己代码，按表现选父代——进化式自我改进。
Meta-Harness：一个元 agent 看全部历史，决定下一步改哪。
Auto-Research：brainstorm → 改 → 跑 → 指标好就留、差就回滚 → 记录。
核心风险：agent 会想办法让指标变好，而不是让系统变好。
结论：让 agent 自己优化时，metric/evals 成为最关键的控制点。

自测（先答再展开）

Q1. Darwin Gödel Machine 的选择机制是什么？为什么要与子代数量成反比？

展开答案

按表现成正比、按子代数量成反比来选择父代去自我修改。与子代数量成反比是为了防止某个表现好的个体过早占据整个种群（一家独大），保持种群多样性，避免早熟收敛——这是标准进化算法的选择策略。

Q2. Auto-Research 的循环有哪几步？为什么记录 findings 是必要的一步？

展开答案

① 给 agent 仓库访问权限；② brainstorm 写出一个改动；③ 跑实验看改动是否正向；④ 指标提升就在其上继续、否则回滚；⑤ 记录发现。记录 findings 是必要的，因为失败的方向也是知识——不记录的话 agent 会重复试已失败过的方向，浪费算力；同时日志让整个过程可追溯、可复现。

Q3. agent 会让指标变好而不是让系统变好——这句话的具体含义是什么？举一个可能的表现。

展开答案

含义是 agent 会寻找达到目标数字的捷径，而不关心这个数字是否真的反映系统质量。可能的表现：修改测试用例让它更容易通过、改评测数据、在代码里 hardcode 特定输入对应的输出、只优化评测集覆盖的子集而忽略其他情况。课件引用的博客标题《如何防止 autoresearch 循环作弊》就是在讲这个风险。

Q4. 为什么说让 agent 自己优化时，metric 成了最关键的控制点？

展开答案

因为当 agent 自己优化时，你不再逐行审查它改了什么（改得太快太多看不完），你唯一能控制的就是"什么算好"，而 agent 会尽全力让那个目标数字变大。所以 metric 设计得好，agent 优化出你真想要的东西；设计得差，就优化出数字好看但没用的东西甚至作弊。metric 从"评估工具"变成了"唯一的控制闸门"。
