记忆的三个开放问题：记什么、信不信、用得对不对

第 0054 课（Lecture07 第 9 课）· 来源：lecture07.pdf p95-103 · 来源文件夹：week4-10.14 · 本课成果：理解记忆的三大未解难题（记/忘的取舍、信任与隐私、过度个性化），并能判断哪些在你的场景里是硬约束

先给结论

三个开放问题（p96）：

① 记什么、忘什么——记忆创建时，未来的相关性是未知的
② 信任、隐私与用户控制——记忆是 agent 的攻击面，也有隐私含义
③ 正确使用记忆——大量"过度个性化"源于记忆误用

这三个问题都没有解。课件把它们放在最后，是告诉你：记忆这块地还没修完。

问题一：记什么、忘什么（p97）

困境（p97 原文）：
  · 记忆创建的那一刻，"未来会不会用到"是未知的
  · 全部保留 → 检索、上下文、维护成本都上升
  · 忘记 → 可能丢掉有用的证据，或未完成的承诺

课件举了个很妙的例子：

"记忆还是玩笑？？？该记哪一面？"

这句话点出了难点：同一句话，记字面还是记语境，结果完全不同。用户说"这个阈值随便啦"，是玩笑还是真的放宽？记错了就是事故。

同样一句 "阈值放宽点吧"：
  记成事实   → 下次真的按放宽执行（如果是玩笑 → 事故）
  记成偏好   → 下次只提示"你倾向放宽"（更安全）
  不记       → 下次再问一遍（低效但无损）
  
→ 医疗场景的默认选择：宁可低效，不能记错

问题二：信任、隐私与用户控制（p98-99）

记忆是攻击面（p98）

可能诱导模型执行被投毒的程序记忆，从而做出危险行为。（Chen et al. 2024, arXiv:2407.12784） 
攻击路径：
  攻击者在某个数据源里埋一段"程序记忆"
      ↓
  记忆系统把它存下来（看起来像正常经验）
      ↓
  agent 在关键时刻召回它、并照着执行
      ↓
  造成危险行为

为什么危险：程序记忆是"怎么做"的规则，
被骗一次，之后每次都会重复执行

这比一次性提示注入更严重：提示注入只影响当次，投毒记忆会持续影响。

隐私（p99）

agent 与世界交互时并不完全理解你想保密什么；带着记忆去做这件事，会暴露个人细节。（Shao et al. 2025, arXiv:2409.00138）

核心问题：模型不知道什么该保密，而记忆让它可以长期、跨会话地累积这些信息。

问题三：正确使用记忆（p100）

LLMs 有时过度热衷使用上下文里的东西。这可以通过更好的检索、或训练模型忽略不重要的上下文来缓解，但两者都没完全解决。而且有些用户比其他人更喜欢个性化。（Hu et al. 2026, arXiv:2601.13722） 
过度个性化的典型表现：
  用户上周提过一次"我对 Python 更熟"
  → 之后所有代码示例都用 Python，哪怕这次需要 C++
  
  用户上个月说"简洁点"
  → 之后连安全警告都用一句话带过

根因：模型"过度热衷"用上下文里的东西，
     缺少"这次该不该用"的判断

SGRT 工程桥：三个问题在你场景里的严重度

问题你的场景严重度对策
记什么忘什么技师口语化指令（"随便啦""差不多就行"）高语含歧义时不自动写入记忆，转为确认；记偏好而非事实
投毒记忆排查 SOP 若来自外部/众包，可能被污染极高SOP 变更必须走审批；记忆写入带来源；定期审计
隐私患者信息、操作员信息极高记忆脱敏；患者信息根本不进记忆；按账号隔离
过度个性化偏好套用到不该用的场景中偏好只影响呈现方式，不影响安全判断

特别强调第二条：程序记忆被投毒是最危险的一种，因为它是"怎么做"的规则，一旦被骗，之后每次都会重复执行。你的 SOP 必须有审批流程和来源记录。

Lecture07 全讲总结

一、动机（p8-13）：三类损失（流程/知识/进度）+ 三项收益（个性化/经验/状态）
二、类型（p14-22）：工作/情景/语义/程序；参数记忆 vs 上下文记忆
三、三问（p23-28）：What 存什么 / When 何时触发 / How 存哪里
四、四模式（p29-66）：
     ① 从经验学流程（Voyager / AWM / Skill Files）
     ② 分层记忆（MemGPT / MemoryOS）
     ③ 反思式巩固（Generative Agents）
     ④ 记忆维护（Sleep Time / A-Mem / Mem0 四动作）
五、评估（p67-94）：四条标准 + 四个基准的演进
六、挑战（p95-103）：记与忘 / 信任与隐私 / 正确使用

贯穿全讲的主线：记忆系统的每个设计选择，都是在"能记住"和"不添乱"之间选一个点。记得越多，检索越难、矛盾越多、攻击面越大。

本课小结

记与忘：创建时不知未来相关性；全留则成本高，忘则可能丢证据。
信任与隐私：记忆是攻击面（投毒的程序记忆会持续生效）；模型不知道什么该保密。
正确使用：模型过度热衷用上下文里的东西，导致过度个性化，两种缓解手段都没完全解决。
共同点：三个问题都没有解——记忆还是个开放领域。

自测（先答再展开）

Q1. "记什么、忘什么"这个困境的本质是什么？课件用"记忆还是玩笑"举例想说明什么？

展开答案

本质是：记忆创建的那一刻，未来会不会用到是未知的；全留则检索/上下文/维护成本上升，忘记则可能丢掉有用证据或未完成承诺。举例想说明：同一句话记字面还是记语境，结果完全不同——"阈值随便啦"如果记成事实会按放宽执行（若是玩笑就是事故），记成偏好则更安全，不记则低效但无损。

Q2. 为什么"投毒的程序记忆"比一次性的提示注入更危险？

展开答案

因为程序记忆是"怎么做"的规则，会被长期保存并在未来反复召回执行。提示注入只影响当次对话，而投毒记忆一旦被存下来，之后每次遇到相关场景都会被激活，"被骗一次，之后每次都重复执行"，且很难被察觉。

Q3. "过度个性化"的表现和根因是什么？

展开答案

表现：用户提过一次"我更熟 Python"，之后所有代码示例都用 Python 哪怕这次需要 C++；说过一次"简洁点"，连安全警告都一句带过。根因：LLM 有时过度热衷使用上下文里的东西，缺少"这次该不该用"的判断；更好的检索和训练模型忽略不重要上下文两种手段都没完全解决。

Q4. 在你的医疗场景里，哪个挑战最严重？为什么？

展开答案

投毒的程序记忆最严重。因为你的记忆里存的很大一部分是排查 SOP（"怎么做"的规则），一旦被污染，之后每次排查都会照着错误规则执行，且程序记忆会被反复召回、很难察觉。另外隐私（患者/操作员信息）也极高。对策：SOP 变更必须审批、记忆写入带来源、定期审计、患者信息不进记忆。
