两代检索器：词频统计 BM25 vs 稠密向量 DPR

第 26 课（Week3 第 4 课）· 来源：lecture03.pdf p40-48 + DPR 论文（Karpukhin et al., 2020）· 本课成果：看懂 BM25 公式每一项在干嘛、理解 DPR 的对比学习训练，以及"混合检索"为什么是工程标配

先给结论

两类检索器各有死穴：BM25（词重叠）几十年仍是使用最广的——它精确匹配关键词，抓得住 ID/错误码/专有名词，但抓不住同义改写；DPR（稠密向量）把 query 和段落都编码成向量算点积，懂语义，但要标注配对数据、且抓不住罕见字面量。两者失败方式不同 → 混合检索（BM25 + 稠密）是工程标配。

工程含义：一个数字说明问题——DPR 只要有 1000 对问答就能超过 BM25。

BM25：词重叠之王（p41-42）

使用最广的稀疏检索（至今）。打分公式（p41）：

score(D, Q) = Σ_{i=1..n}  IDF(q_i) · [ f(q_i,D)·(k1+1) / ( f(q_i,D) + k1·(1 − b + b·|D|/avgdl) ) ]

IDF(q_i) = ln( (N − n(q_i) + 0.5) / (n(q_i) + 0.5) )
项含义（大白话）
IDF(q_i)词越罕见越重要（"the"几乎没用，"ERROR_4021"很关键）
f(q_i, D)该词在文档里出现了几次
k1词频饱和参数：出现 10 次不比出现 3 次强多少
b 与 |D|/avgdl文档长度归一化：长文档不该仅因长就得分高
N / n(q_i)总文档数 / 含该词的文档数

p42 图：IDF 对比 + 词频饱和——同一个词反复出现，边际增益递减。

DPR：稠密段落检索（p43-48）

双编码器（bi-encoder）：query 和段落各自过 BERT 成向量，算点积：

p(z|x) ∝ exp( d(z)ᵀ · q(x) )
d(z) = BERT_d(z)      # 段落编码器
q(x) = BERT_q(x)      # 查询编码器
top-k: 用 MIPS（最大内积搜索）求解——可预先算好所有段落向量

训练：对比学习（p47）

用in-batch negatives（批内负例）+ BM25 硬负例做对比损失——正例是标注的"问题-正确段"对，负例是同批其他段与 BM25 检索到的"像但不对"的段。

效果（p47-48）

  • DPR 在 5 个数据集中的 4 个上超过 BM25（top-20 / top-100 检索准确率）。
  • 1000 对 QA 就够超过 BM25；无需额外预训练，端到端也超过 ORQA、REALM。

BM25 vs DPR 一张表

BM25（稀疏）DPR（稠密）
原理词重叠 + IDF 加权向量点积（语义相似）
擅长精确字面：ID、错误码、人名语义匹配、同义改写
死穴改写/同义词罕见字面量；需标注配对
训练数据无需训练（统计）需配对（1000 对起步）

为什么用混合检索（p49，下节细讲）

正因为两者失败方式不同，工程上常同时跑两个检索器再融合排序——embedding 抓语义、BM25 抓精确词。

对你 SGRT 系统的含义

  1. 错误码/设备 ID 必须靠 BM25：稠密向量对"ERROR_4021"这种罕见字面量不敏感，纯向量检索会漏。这是很多"检索不到错误码"事故的根因。
  2. 语义问题靠 DPR 类："怎么处理标定失败"要匹配到写着"重新采集标定板"的段落——字面不同、语义相同。
  3. 结论：直接上混合。别在 BM25 和 DPR 里二选一，两个都跑再融合（下节课给 RRF 公式）。

自测（先答再展开）

Q1. BM25 里 IDF 的作用是什么？举一个你会遇到的例子。

展开答案

IDF 让罕见的词权重更高。例："ERROR_4021"很罕见、IDF 高，命中它比命中"的/是"这类高频词更有信息量。

Q2. BM25 和 DPR 各自的死穴是什么？

展开答案

BM25 抓不住同义改写/语义匹配；DPR 抓不住罕见字面量（ID/错误码），且需要标注配对数据训练。

Q3. DPR 的对比学习用了哪两类负例？为什么需要硬负例？

展开答案

批内负例（in-batch negatives，同批其他段落）+ BM25 硬负例（BM25 检索到但实际不对的段）。硬负例更难、更接近正例，能逼模型学到更细的区分边界。

Q4. 你的设备排查 RAG，为什么必须上混合检索而不是纯向量？

展开答案

因为排查里大量查询含精确字面量（错误码、设备 ID、参数名），纯稠密向量会漏掉这些罕见词；BM25 负责精确匹配、稠密负责语义，两者融合才能都覆盖。
