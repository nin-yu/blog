推理四招：从“纯想”到“边想边做”再到“反思”

第 6 课（共 13 课）· 重建 v3 · 本课成果：能讲清 CoT/ReAct/SC/Reflexion 各自机制与适用场景，并复述苹果遥控器案例 · 对应第 5 课 loop 的 Think 环节

先给结论

推理（Think）有四层“加料”方式，越往后越强、也越贵：
CoT（先一步步想再答）→ ReAct（边想边做、用观察校正）→ Self-Consistency（多次想、投票取一致）→ Reflexion（从失败里反思、沉淀成下次的提示）。
核心权衡：推理换准确率，代价是 token 与延迟。

为什么 agent 需要“推理”（原理，一段话）

Obs→Act 的直接映射常常是难的。人做饭时“盐没了 → 去右边柜子拿酱油”不是条件反射，而是中间转了几道弯推出来的。LLM 同理：给它一个中间推理步骤，它才能把“观察”和“该做的动作”连起来——这就带来泛化（新场景也推得动）和对齐（你能看懂它为什么这么做）。

四招逐个拆（机制 + 弱点）

方法机制弱点 / 修补
CoT 思维链
(Chain-of-Thought)		让模型“先一步步推理，再给答案”推理中途可能幻觉且无从校验
ReAct
(Reason + Act)		推理与行动交错：想一步→做一个动作→拿到观察→再想把观察 (Obs) 喂回来缓解幻觉；普遍优于“只行动不推理”
Self-Consistency用 CoT 采样多条推理路径，取最一致的答案（投票）成本×N；对“有唯一正确答案”的题最有效
Reflexion用自然语言反思任务反馈，把失败的长轨迹蒸馏成“自我提示”留到下次需要能拿到反馈信号（成败/评分）

延伸：多智能体辩论（Du et al., 2023）让多个 LLM 各自推理再互相辩；编排器（Orchestrator）用一个总控协调多个子 agent（如 Magentic-One）。属于“多脑”路线，本课程先不深入。

经典案例：苹果遥控器（课件 p35-36，务必看懂）

问：除了 Apple Remote 本身，还有哪些设备能控制它当初被设计来控制的那款程序？

纯推理（CoT）：Apple Remote 控制 Apple TV；Apple TV 可由 iPhone/iPad/iPod Touch 控制。→ 答“iPhone/iPad/iPod Touch”。
错在哪：漏了“键盘功能键”这个正确答案。它的推理链里少了一次“去查”的校正。

ReAct（边想边做）：Thought1 搜 Apple Remote → Obs 得知它控制 Front Row → Thought2 改搜 Front Row → Obs 没找到，提示“Front Row (software)” → Thought3 搜 Front Row (software) → Obs 得知它由 Apple Remote 或键盘功能键控制 → Thought4 得正确答案。
对在哪：每次“观察”都把推理拽回事实，幻觉没机会跑偏。

结论（背下来）：ReAct 普遍优于纯 Act；CoT 的严重问题是幻觉，ReAct 靠“观察”落地能缓解幻觉。这正是第 5 课把 Obs 放进环里的原因。

对照你熟悉的东西（工程桥）

  • CoT ≈ 让算法“写出推导过程”，便于你审；但推导本身可能错。
  • ReAct ≈ 迭代配准：每算一步就看残差，用真实反馈纠偏，而不是一口气算到底。
  • Self-Consistency ≈ 多组初值/多次配准取最一致结果——用重复换稳定性。
  • Reflexion ≈ 把每次标定失败的原因记成 SOP 条目，下次自动规避。

更好懂的比喻：走迷宫（一步一探，而非一条路走到底）

如果上面的案例还嫌绕，用走迷宫来理解 CoT 与 ReAct 的差别——一试就通：

  • CoT = 凭脑子里的地图，一次性画出路线：模型没在“走”迷宫，它在回忆迷宫。它照着印象（“苹果的控制器就是 iPhone”）直接规划一条路线，走到底。
    印象里缺那条岔路（“键盘也能控 Front Row”），就漏了真答案，而且它自己不知道走错了。
  • ReAct = 摸黑走，每到一个岔路口就伸脚探一下：探到的结果是硬事实（Observation），不是印象。
    哪怕印象里没这条路，脚一探也知道——“键盘功能键”就是这么被探出来的。

关键部件 = 那只“探路的脚”（Observation）：没有它，ReAct 就退化成 CoT（只剩干想）；有它，模型每一圈都被事实拽住一次，幻觉没机会连成一条链。

顺带解释一个工程细节：为什么 agent 要有最大步数上限（如 MaxToolRounds）？
因为“每步都探路”虽好，但岔路口无限多或原地打转时，会鬼打墙——无限走、烧 token、出不来。 所以必须设“最多走 N 步 + 无进展即停”。（这正是第 6 课结尾 Reflexion/可靠性会再提到的保护逻辑。）

一句话完整版：CoT = 凭印象一次性画路线（可能画错还自信）；ReAct = 每个岔路口伸脚探一下再选（慢，但踩在真实上）；但探路也必须限步数，否则鬼打墙。
换成控制论的词：CoT 是开环推理，ReAct 是闭环推理——Observation 就是传感器读数。

自测

Q1. 苹果遥控器案例里，CoT 为什么答错、ReAct 为什么答对？

展开答案

CoT 只靠语言内部推导，链条中漏了“键盘功能键”，且无外部信息纠偏，于是幻觉式地给了错误答案。ReAct 每一步都去检索、用 Obs 校正，最终把“键盘功能键”查出来。

Q2. Self-Consistency 与 Reflexion 的核心区别？

展开答案

SC 是“同一时刻多采样、投票取一致”（横向重复）；Reflexion 是“跨尝试的纵向学习”——把上次失败的反思留成提示，改进下一次。一个提升单次稳定性，一个提升长期表现。

Q3. 什么时候不该上多路径推理（SC）？

展开答案

当成本/延迟敏感、且任务没有唯一正确答案（开放生成、创意类）时。SC 的收益主要来自“多选题有唯一解”，开放任务里投票意义不大、还徒增成本。

Q4. 把“反思路线（Reflexion）”落到你的 SGRT 场景，可以怎么做？

展开答案

例：每次标定/配准失败后，让 agent 用自然语言总结“这次为什么失败”（证据不足？门控时机偏了？遮挡？），把结论沉淀成下次的先验提示或检查项。这就是把一次性排错变成可复用的程序记忆（第 7 课）。

Q5. 用“走迷宫”比喻说说：CoT 与 ReAct 的本质差别是什么？为什么 agent 要设最大步数上限？

展开答案

CoT 是“凭脑子里的地图一次性画出路线”——它在回忆迷宫而非走迷宫，印象里有错/有漏也不自知；ReAct 是“每到一个岔路口就伸脚探一下”——Observation 是硬事实（探路的脚），每步把推理拽回现实。最大步数上限则是防“鬼打墙”：探路虽好，但打转/岔路无限时会无限走、烧 token，故须“最多 N 步 + 无进展即停”。一句话：CoT 是开环推理，ReAct 是闭环推理。
