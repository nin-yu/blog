Agentic RAG：决定"要不要查、查什么、够不够"

第 29 课（Week3 第 7 课）· 来源：lecture03.pdf p56-61 · 本课成果：理解普通 RAG 与 agentic RAG 的分界、三个决策点，以及 Self-RAG / CRAG / Search-R1 三种把"检索"变成"可学习动作"的路子

先给结论

前面所有 RAG 都只擅长"回答一个问题"，但没有一个会决定：要不要检索、该问什么、什么时候停。Agentic RAG 把检索变成 agent 主动采取的一个动作，三个决策点：(1) 直接答还是先检索；(2) 该发什么查询；(3) 结果够不够好（要不要再查）。

工程含义：这正是你 MISSION 里"故障排查"的形态——路径未知，得边走边查。三条技术路线：Self-RAG（自学检索+自我批判）、CRAG（用 critic 给检索结果打分）、Search-R1（用 RL 学搜索策略）。

分界线：固定检索 vs 检索即动作（p56）

课件原话大意：迄今为止的一切都只把"回答一个问题"做好，但都不决定是否检索、问什么、何时停。Agentic RAG 的主张：

  • 检索应是 agent 采取的动作（不是每轮都无条件先检索）。
  • 三个决策：
    1. retrieve or answer directly：这题需要查资料吗，还是我能直接答？
    2. what query to issue：要发什么查询？（还能基于上一步结果改写查询）
    3. whether the result is good enough：检索到的够不够，要不要再查？
对照 Week1 第 5 课的 agent loop：普通 RAG = 固定管线（workflow）；agentic RAG = 把"检索"作为 Act 放进 Obs→Think→Act 的循环里。查不查、查几次，由模型当场决定。

路线 1：Self-RAG（p57）

Asai et al., 2024：让模型学会"检索、批判、生成"，以增强生成质量、事实性与可验证性。要点：模型自己产出"是否需要检索"以及"检索到的段落相不相关/答案是否有据"的反思标记，据此调整。= 把批判内化成模型能力。

路线 2：CRAG（p58）

Yan et al., 2024：加一个 critic（评估器）给检索结果打分——评估检索到的文档与输入的相关性并给出置信度，据此触发不同的知识检索动作（例如：相关度高就直接用、中等就补充检索、太低就走别的路径）。= 用外部 critic 做"检索质量闸门"。

路线 3：Search-R1（p59-61）

Jin et al., 2025：用强化学习优化"多轮搜索交互"的推理轨迹——即直接训练"搜索策略"本身（何时搜、搜什么、何时停），而不是靠提示词规定。

三条路线对照

方法核心机制"要不要查/够不够"由谁决定
Self-RAG模型自学检索+自我批判，输出反思标记模型自身的反思标记
CRAG独立 critic 给检索结果打分+置信度外部评估器
Search-R1RL 直接优化多轮搜索的推理轨迹学出来的搜索策略

对你 SGRT 系统的含义

  1. 简单问答用固定 RAG 就够：日常 QA 走 Week1 第 12 课判定的 workflow（固定"检索→生成"），别上 agentic 的复杂度。
  2. 故障排查才用 agentic RAG：先查哪份日志取决于日志内容，检索次数也不固定——这正是 agentic RAG 的主场。
  3. 从 CRAG 式闸门起步：不要一上来训 RL（Search-R1 成本高）。最实用的第一版是"检索 → critic 打相关性分 → 分不够就改写查询再查"，可控、可评估、可加人审点。

自测（先答再展开）

Q1. 普通 RAG 和 agentic RAG 的本质区别？

展开答案

普通 RAG 是固定管线：每轮无条件检索一次再生成。Agentic RAG 把检索变成 agent 主动决定的动作，由模型决定要不要检索、发什么查询、结果够不够——是带检索动作的 loop。

Q2. Agentic RAG 的三个决策点是什么？

展开答案

(1) 直接答还是先检索；(2) 该发什么查询；(3) 检索结果够不够好、要不要再查。

Q3. Self-RAG、CRAG、Search-R1 各自用什么决定"检索质量/策略"？

展开答案

Self-RAG：模型自学检索并自我批判（反思标记）；CRAG：独立的 critic 给检索结果打相关性分/置信度；Search-R1：用 RL 学出多轮搜索策略。

Q4. 你的故障排查 agent，第一版该怎么起步？

展开答案

用 CRAG 式闸门：检索 → critic 打相关性分 → 分不够就改写查询再查，够了就生成。可控、可评估、可插人审点；先别上 RL（Search-R1 成本高）。
