拿到一个真实任务，先判：Workflow 还是 Agent？

第 12 课（共 13 课）· 前面 11 课的零件在此合体 · 本课成果：掌握“四问法 + 判定法则 + 最小可评估 MVP 清单”，能对任意 SGRT 环节做结构化判定（对应 MISSION 第 1 条成功标准）

先给结论（判定一张表）

Workflow 和 Agent 都是“LLM + 组件”的复合系统（第 1 课），唯一区别是谁决定步骤（课件 p56）：
代码定步骤 = Workflow（例：Agentless、AlphaCode 2 的固定管线）；LLM 定步骤 = Agent（例：SWE-agent、ReAct）。

判定法则：能预先写清步骤、且中间结果可检查 → Workflow；不知道最优步骤、必须靠环境实时反馈决策 → Agent。先加约束，后加自由。绝大多数工程价值来自“固定管线 + 少量 LLM 判断点”。

四问法（30 秒判定一个任务）

  1. 步骤已知吗？能预先写清每一步 → workflow；要走一步看一步 → agent。
  2. 中间结果能检查/中断吗？能 → 可拆成 workflow 或 agent 内设校验点；不能 → 谨慎，错误会复合（第 10 课）。
  3. 失败代价多高？高 → 无论哪种范式，先上人审/沙箱/护栏（第 9、11 课）。
  4. 怎么算“对”？有客观指标（准确率/完成率/耗时/成本）→ 才可评估（第 10 课）；没有 → 先定指标再动手。

对照表（维度全对照）

维度WorkflowAgent
步骤顺序固定、可预测动态，按 Obs 当场决定
适合步骤已知、结果可枚举路径未知、要先想再做
成本 / 延迟低、可预算高（多次调用、反复检索）
可靠 / 可评估容易（因果清晰）难（无固定轨迹，要做一致性评估）
代表Agentless、AlphaCode 2ReAct、SWE-agent

最小可评估版本（MVP 设计清单，第一版就照这个来）

  1. 锁定一个子任务（别一口吃整条大流程）。
  2. 定指标：一个客观数（准确率/完成率/耗时/成本）。
  3. 选范式：用上面的四问法判定。
  4. 接最少外部件：先只加一项（RAG 或一个只读工具），再逐步叠（第 8、9 课）。
  5. 上护栏：沙箱 + 人审点 + 事后检查（第 9、11 课）。
  6. 当场评估：跑 N 次看一致性、加扰动看鲁棒性（第 10 课）。

实战演练：你的三个候选任务（先自己判，再展开）

Q1. SGRT 自动标定的日常 QA（流程固定：拍照 → 提取 → 算残差 → 对照阈值 2mm/1° → 出报告）——workflow 还是 agent？

展开判定

Workflow。步骤完全已知、结果可枚举（通过/不通过）、指标现成（2mm/1°）。LLM 只需一个判断点：把异常摘要成报告文字。四问全绿。

Q2. 胸腹表面配准结果的“自动质检 + 异常定位”助手——workflow 还是 agent？

展开判定

混合：固定预检管线 + 一个 LLM 判断点。数值阈值检查（RMS/覆盖率）是 workflow；“残差图上这片异常更像呼吸伪影还是遮挡”属于经验判读——RAG 案例库 + LLM 判读，但输出仅作建议。这是“固定管线 + 少量 LLM 判断点”的典型。

Q3. 设备日志的“缺陷排查”智能助手（路径未知：可能要查日志、查错误码表、翻历史工单）——workflow 还是 agent？

展开判定

Agent（ReAct 式）。步骤无法预写：先看哪份日志取决于日志里有什么，每一步的观察决定下一步。护栏：工具全部只读、关键结论人审。这是你 MISSION 里“真 agent”的进阶目标。
