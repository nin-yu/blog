语言模型是什么：概率、生成与采样

第 0009 课（Lecture02 第 1 课）· 来源：lecture02.pdf p6-23 · 来源文件夹：week2-9.28 · 本课成果：理解语言模型的概率本质、采样策略的取舍，能为不同任务选对解码参数

先给结论

语言模型的数学定义（p7）：

一个 token 序列的概率 = 从第一个到最后一个 token，每个 token 在给定前文时的条件概率的连乘

P(序列) = P(t₁) × P(t₂|t₁) × P(t₃|t₁t₂) × …

它是生成式模型（学数据分布），不是判别式（学分类边界）。所以可以从它采样——这就是为什么同一个 prompt 两次跑结果不同。

一、语言模型的数学定义（p7-9）

一个 token 序列的概率：

  P("The class was about agents.") 
    = P(The) × P(class|The) × P(was|The class) 
      × P(about|The class was) × P(agents|The class was about) 
      × P(.|The class was about agents)

  p8 给的数字例子：这个序列的概率 = 0.0377

→ 每一步都是"给定前面所有 token，下一个 token 的概率"
→ 连乘起来就是一整句话的概率

这个定义的直接推论：模型本质上是一个"下一个 token 的概率分布生成器"。它不"理解"整句，它只做一件事——每次预测下一个词。

二、生成式 vs 判别式（p10-12）

判别式 Discriminative生成式 Generative
学什么区分类别（P(类别|输入)）学数据的分布（P(数据)）
例子朴素贝叶斯、分类器语言模型、扩散模型
能做什么判断"是/不是"能生成新样本

课件的 Knowledge Check（p12）专门点出一个陷阱：

问：用上面那个公式建模 token 序列概率的语言模型，是生成式还是判别式？
"这不是陷阱题，但这里的记法可能让人觉得是陷阱。" 
为什么容易答错：
  公式写成 P(y|x) 的样子时，看起来像判别式（条件概率）
  但它建模的是"整个序列的联合分布"
  → 所以是生成式

关键区分：
  判别式：P(猫|图) —— 只关心分类
  生成式：P(图) 或 P(句子) —— 关心"什么样的东西会出现"

三、能采样意味着什么（p13-19）

LMs are generative, which means we can sample from them.（p13）

采样过程（p15-19）：
  1. 输入 "The class was about"
  2. 模型给出下一个 token 的概率分布：
       to     0.3171
       as     0.0491
       the    0.0360
       a      0.0330
       two    0.0147
       how    0.0124
       ...
  3. 按这个分布抽一个（比如抽到 "to"）
  4. 把 "to" 接到输入后面，重复

p19 的结果："The class was about The to begin."
  → 这就是为什么同一个 prompt 两次结果不同
  → 采样本身引入随机性

四、Temperature：调整随机程度（p20）

做法（p20 原文）：
  把所有概率除以某个温度 T，然后重新归一化使和为 1

数学：P'(w) = P(w)^(1/T) / Σ P(w')^(1/T)

效果：
  T → 0    概率分布变尖，几乎总选最高概率的（确定性）
  T = 1    保持原分布
  T > 1    分布变平，低概率词也有机会被选中（更有创意）

直觉：T 是"随机程度的旋钮"

五、Beam Search（p21）

不是每次抽一个，而是同时保留 k 条候选路径

  步骤 1: "The class was about" → 保留概率最高的 3 个分支
  步骤 2: 每条分支各扩展 → 总共 9 条 → 再保留最好的 3 条
  步骤 3: 重复……

优点：可能找到比贪心更好的整体序列（因为不只看单步最优）
代价：时间和内存都是原来的 k 倍

六、怎么选采样策略（p22）——本课考点

· 每种采样策略有不同的取舍
· Temperature 和 Top-p/Top-k 帮助提升多样性
· 用什么策略取决于你的任务：
　- 数学/代码更可预测（用低温度）
　- 创意写作可能受益于更高多样性（用高温度）
· 策略也取决于预算（beam search 时间和内存复杂度更高） 
实用对照表：

  任务类型          temperature   说明
  ─────────────────────────────────────────
  代码生成/修复      0 ~ 0.2      要确定性，不能"创作"
  结构化输出（JSON）  0 ~ 0.2      格式必须稳定
  数据提取           0            完全不要创造力
  常规问答           0.3 ~ 0.7    平衡
  头脑风暴/创意      0.8 ~ 1.2    要多样性
  需要多次采样投票    0.7 ~ 1.0    需要多样化的路径

SGRT 工程桥：你的场景该用什么温度

【诊断类任务 → 低温度（0 ~ 0.2）】
  你让 agent 判断"这次残差升高是什么原因"
  → 这是有正确答案的判断，不需要创意
  → 高温度会让它偶尔"编"一个不存在的根因
  → 建议 0.1

【参数建议生成 → 中低温度（0.2 ~ 0.4）】
  "建议调整哪些参数" —— 有标准做法但不唯一
  → 稍高一点能给出多个候选
  → 但太高会建议离谱的值

【报告撰写 → 中温度（0.4 ~ 0.6）】
  给工程师看的说明，需要组织语言但不能编造
  → 中等即可

【绝对不要用于】
  · 安全阈值判断 —— 必须确定性
  · 数值计算 —— 不能靠模型"生成"数字

【一个容易被忽略的点】
  温度是"整个生成过程"统一的
  如果你的 agent 既要判断（需低温）又要解释（可高温）
  → 拆成两次调用，各自设温度
  → 这比调一个折中值好

本课小结

定义：token 序列概率 = 各条件概率连乘；本质是"下一个 token 的分布生成器"。
生成式：学数据分布，所以能采样——这是结果不确定的根源。
Temperature：除以 T 再归一化；T 小则确定，T 大则发散。
Beam Search：保留 k 条路径，质量可能更好但 k 倍成本。
选策略：代码/数学用低温，创意用高温，也要看预算。

自测（先答再展开）

Q1. 语言模型是生成式还是判别式？为什么公式写成条件概率的样子容易让人答错？

展开答案

是生成式。公式写成 P(y|x) 的形式时看起来像判别式（只关心分类），但它建模的是整个序列的联合分布——每一步预测"给定前文下一个 token 是什么"。判别式只学 P(类别|输入) 用来分类，生成式学 P(数据) 所以能生成新样本。

Q2. Temperature 的数学操作是什么？T→0 和 T→1 分别是什么效果？

展开答案

把所有概率除以温度 T，然后重新归一化使和为 1（即 P'(w) = P(w)^(1/T) / ΣP(w')^(1/T)）。T→0 时分布变尖，几乎总选最高概率的 token，接近确定性输出；T=1 时保持原分布；T>1 时分布变平，低概率 token 也有机会被选中，输出更多样。

Q3. 什么任务该用低温度、什么该用高温度？各举一例。

展开答案

低温度（0~0.2）用于需要确定性的任务：代码生成/修复、结构化 JSON 输出、数据提取、以及数学计算——这些有正确答案，高温度会导致"创作"出不存在的根因或错误格式。高温度（0.8~1.2）用于需要多样性的任务：头脑风暴、创意写作、以及需要多次采样投票时（要多样化的推理路径）。

Q4. 你的 agent 既要判断又要解释，温度该怎么设？为什么不能设一个折中值？

展开答案

应该拆成两次调用，判断用低温（0.1 左右）、解释用中温（0.4-0.6）。因为温度是整次生成统一生效的——设一个折中值意味着判断环节还不够确定（可能编造根因），而解释环节又不够灵活（语言生硬）。拆开后各环节都拿到最合适的参数，代价只是多一次调用。
