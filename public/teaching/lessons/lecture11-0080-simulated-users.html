来源四：模拟用户与环境

第 0080 课（Lecture11 第 6 课）· 来源：lecture11.pdf p52-57 · 来源文件夹：week6-10.28 · 本课成果：掌握 τ-bench/APIGen-MT/DreamGym 三种模拟的对象与风险梯度，理解四来源组合策略，能判断本项目该用真人工程师而非 LLM 模拟用户

先给结论

核心思路（p53）：一个 LLM 可以扮演用户、环境，或者两者都扮演。

三个代表，各扮不同的东西：
τ-bench【工具】——LLM 扮演零售/航空场景里的顾客
APIGen-MT【工具】——LLM 评审员审核任务蓝图
DreamGym【Web】——LLM 当「经验模型」，预测下一个[状态]

为什么这条路重要：交互的另一半（用户）本来无法规模化，现在能了。

一、为什么需要模拟用户（p52-53）

前面三种来源都缺一个东西：交互的动态性

  人类示范：人做一遍 → 静态轨迹，没有追问、没有改需求
  挖掘：网上挖 → 没有交互历史
  合成：造任务 → 但任务描述是死的

真实场景里 agent 要面对的是：
  · 用户说得不清楚 → 要问
  · 用户改主意 → 要调整
  · 用户不满意 → 要解释
  → 这些在静态数据里全都没有

→ 所以需要"模拟用户"

二、τ-bench：LLM 演顾客（p54）

τ-bench【工具】：一个 LLM 在零售和航空[场景]里扮演顾客 
三方结构（Lecture04 第 0030 讲提过）：
  Tool  —— 有状态、会失败的工具
  Agent —— 被测模型
  User  —— LLM 扮演的顾客

为什么必须加 User：
  · 顾客会追问（"为什么不给我退？"）
  · 顾客会改需求（"那我要换个航班"）
  · 顾客会表达不满
  → 这些逼出 agent 的"该问就问"能力

评估维度（对应 0081 前的内容）：
  · 策略：规则说不该做时是否做了
  · 交互：该问用户时是否自己假设了
  · 非确定性：Pass^k（同一任务多次是否都成功）

这个设计解决了一个原本无解的问题：

之前：要测"多轮交互能力"，就得雇人扮演用户
      → 每个任务都要人实时对话
      → 完全无法规模化

现在：LLM 扮演用户
      → 可以并行跑上千个对话
      → 可以固定"用户剧本"保证可复现
      → 还可以故意制造难缠用户（测鲁棒性）
      
代价：
  · LLM 演的用户可能"太好说话"或"太不合理"
  · 与真实用户分布有偏差

三、APIGen-MT：LLM 当评审员（p55-56）

APIGen-MT【工具】：LLM 评审员用[多个标准]审核任务蓝图 
流程（多智能体式的数据生产）：
  ① 生成任务蓝图（任务描述 + 预期工具调用）
  ② LLM 评审员审核：这任务合理吗？工具选择对吗？
  ③ 通过审核的才保留
  ④ 多轮迭代提升质量

为什么需要审：
  合成的任务容易"看起来对但实际不合理"
    · 任务描述与工具能力不匹配
    · 预期调用链有逻辑错
    · 参数值不合常理
  → 靠自动评审过滤

注意这里 LLM 的角色：
  不是判"agent 做得好不好"
  而是判"任务本身好不好"
  → 这是数据质量把关，不是模型评测

四、DreamGym：LLM 当"经验模型"（p57）

DreamGym【Web】：一个 LLM 「经验模型」预测下一个[状态] 
这个最激进：不只模拟用户，还模拟环境本身

做法：
  一个 LLM 学习"在某个状态下，执行某动作会得到什么观察"
  → 替代真实环境
  → agent 在"梦境"里训练

好处：
  · 不需要真实环境（不需要跑真网站、真 API）
  · 可以造出真实世界罕见的状态
  · 完全可控、可复现、可无限次交互

风险：
  · 经验模型会错（预测的状态与真实不符）
  · agent 可能学会"对付梦境"而不是真实世界
  · 误差会累积（多步之后偏差巨大）

→ 这是 0081 课"过拟合到 harness/环境"的极端形式

五、三种模拟的对比

案例模拟什么解决什么主要风险
τ-bench用户多轮交互无法规模化模拟用户与真人有分布偏差
APIGen-MT评审员合成任务质量不可控评审员本身会错，可能一致性地漏
DreamGym环境（状态转移）真实环境昂贵/无法造罕见情况经验模型误差累积，学成"对付梦境"
一个梯度很清楚：

  模拟用户   → 风险最小（用户行为本来就是多样化的）
  模拟评审   → 风险中等（评审标准可以人工校准）
  模拟环境   → 风险最大（状态转移错一步，后面全错）

→ 能用真环境就用真环境
→ 模拟环境只在"真实环境不可得"时用

六、四种来源的整体对比

来源真实性规模成本最佳用途
人类示范最高最低最高种子数据、难点覆盖
挖掘高（自带验证的最好）高低规模化基础数据
合成环境中高（验证真实）中高中可控难度、罕见情况
模拟用户/环境中到低最高低（算力）交互训练、极端情况
实践中的组合（几乎所有大项目都是这样）：

  人类示范（少量高质量种子）
    → 挖一批真实数据（打底）
    → 合成环境（补罕见和难度梯度）
    → 模拟用户（训练交互能力）
    → 用真实测试集做最终验证

→ 不要只用一种来源

SGRT 工程桥：你的"模拟用户"就是工程师

【好消息：你的用户是内部工程师，可以自己扮演】

τ-bench 用 LLM 演顾客，因为真实顾客请不到
你的场景不需要：
  ✘ 不用 LLM 演工程师
  ✔ 直接用真人（你的同事）演
  → 因为工程师就在公司里，成本低且质量高

【具体做法：模拟值班对话】

  一个人演值班工程师，按真实习惯提问：
    第 1 轮："3 号机报警了，你看下"
      → 信息不足，agent 应该问："哪类报警？什么时间？"
    第 2 轮："残差，昨晚开始的"
      → 还是不够，agent 应该问："哪个区域？夜间有什么规律？"
    第 3 轮："腹部，白天正常"
      → 现在信息够了，可以开始查

  → 这个对话本身就是在测"该问就问"的能力
  → 而且真实（真人演的就是真人）
  → 不需要 LLM 模拟

【用这个训练/测试什么】
  · 信息不足时是否追问（不是硬猜）
  · 用户改需求时是否调整（"算了先不管 3 号，看 5 号"）
  · 用户表达不满时是否解释（"上次你也是这么说的结果没用"）
  → 这三类交互是真实工作的核心
  → 静态任务数据里完全没有

【不要做的：模拟环境】
  ✘ 不要用 LLM 预测"设备状态会怎么变"
    → 物理系统不能用语言模型预测
    → 误差会立刻累积到无意义
  ✔ 用真实的设备/仿真器（你有）
  → 这是你相对公开数据集的最大优势之一

本课小结

核心思路：一个 LLM 可以扮演用户、环境或两者。
τ-bench：LLM 演顾客——让多轮交互可规模化。
APIGen-MT：LLM 当评审员审核任务蓝图——数据质量把关。
DreamGym：LLM 当经验模型预测下一状态——最激进也最危险（误差累积）。
风险梯度：模拟用户 < 模拟评审 < 模拟环境。
实践：四种来源组合使用，不要只用一种。

自测（先答再展开）

Q1. 为什么前面三种来源都需要「模拟用户」这一层？

展开答案

因为前三者都缺交互的动态性：人类示范是静态轨迹（人做一遍，没有追问和改需求）、挖掘没有交互历史、合成任务描述是死的。而真实场景里 agent 面对的是说得不清楚的用户、会改主意的用户、会不满的用户——这些「该问就问」「该调整就调整」的能力在静态数据里完全没有，必须靠模拟用户来产生多轮交互数据。

Q2. τ-bench 的三方结构是什么？它解决了什么原本无解的问题？

展开答案

三方：Tool（有状态、会失败的工具）、Agent（被测模型）、User（LLM 扮演的顾客）。解决的是「多轮交互能力无法测试」——之前要测多轮交互就得雇人实时扮演用户，每个任务都要人对话，完全无法规模化；现在 LLM 扮演用户可以并行跑上千个对话、固定剧本保证可复现、还能故意制造难缠用户测鲁棒性。

Q3. DreamGym 的「经验模型」模拟什么？为什么它的风险最大？

展开答案

模拟环境的状态转移：一个 LLM 学习「在某个状态下执行某动作会得到什么观察」，从而替代真实环境，让 agent 在「梦境」里训练。风险最大因为：① 经验模型会预测错（状态与真实不符）；② 误差会逐步累积（多步之后偏差巨大）；③ agent 可能学会「对付梦境」而不是真实世界。这是过拟合到环境的最极端形式。梯度：模拟用户 < 模拟评审 < 模拟环境。

Q4. 你的场景为什么不需要 LLM 演用户，但绝不能用 LLM 模拟环境？

展开答案

不需要 LLM 演用户：你的用户是内部工程师，就在公司里——直接真人扮演成本低、质量高（真人演的就是真人，没有分布偏差）。绝不能用 LLM 模拟环境：设备是物理系统，状态转移由物理规律决定，不能用语言模型预测——误差会立刻累积到无意义。你应该用真实设备或仿真器（你有这个资源），这是相对公开数据集的最大优势之一。
