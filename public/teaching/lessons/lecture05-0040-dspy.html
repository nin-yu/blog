DSPy：把"手写提示"换成"声明签名 + 自动优化"

第 40 课（Lecture05 第 2 课）· 来源：lecture05.pdf p21-51 + DSPy 论文（Khattab et al.）· 本课成果：理解 DSPy 三件套（Signatures 声明 What / Modules 组合 How / Optimizers 按指标自动改进），以及"编译器"如何自动优化 pipeline

先给结论

传统做法是"手写一长串试出来的提示模板"（脆弱、难维护）。DSPy 的转向：把 LM pipeline 抽象成"文本变换图"——用 Signatures 声明输入/输出契约（What）、用 Modules 组合程序逻辑（How）、用 Optimizers（编译器） 按给定指标自动改进提示或权重。

论文结论（本地 DSPy 论文）：几行 DSPy + 编译几分钟，就让 GPT-3.5 / llama2-13b-chat 自举出超过标准 few-shot 的 pipeline（通常超 25%/65%）。

DSPy 三件套（p22，原文）

组件一句话回答的问题
Signatures 签名严格定义模型的输入/输出What（要什么）
Modules 模块把签名和程序逻辑组合成可调用函数How（怎么做）
Optimizers 优化器按指标改进程序的提示或权重改进（怎么更好）

Signatures（p24-28）

把输入/输出约定成签名——而不用手写整段提示。课件 p26 的注解点出痛点："这些没遵循同一格式，不好"——即手写输出格式易乱；签名强制契约一致。

示意：question -> answer          （一个问答签名：输入 question，输出 answer）
系统会根据签名自动生成提示，并把输出解析回结构字段。

Modules（p29-34）

把签名 + 程序逻辑组合成可调用的函数。常见内置模块（p51）：dspy.Predict、dspy.ChainOfThought、dspy.BestOfN…

Optimizers / 编译器（p35-44）

优化器在给定 Data（数据） 和 Metric（指标） 下，改进程序的提示或权重。论文称其为"编译器（compiler）"——把任何 DSPy pipeline 优化到最大化某个指标。

原始 pipeline（签名 + 模块）
      │  给定 Data + Metric
      ▼
   Optimizer / Compiler
      │
      ▼
优化后的 pipeline（提示/权重被自动调好）

DSPy 也能表达 agent（p45-50, p51）

p45-50 展示用 DSPy 搭 Agents；p49-50 提到 ReAct 与 RLM。p51 总结：

• Signatures 定义输入/输出契约；
• Modules 组合并规定"如何履行签名契约"（dspy.Predict、dspy.ChainOfThought、dspy.BestOfN…）；
• Optimizers 能在给定数据与指标下改进提示/权重；
• DSPy 内置让 agent 履行签名的模块：dspy.ReAct、dspy.RLM。

DSPy 论文的关键主张（本地论文摘要）

  • 把 LM pipeline 抽象为 文本变换图（text transformation graphs）——LM 通过声明式模块（declarative modules）被调用。
  • 模块是参数化的：能"学会"如何组合提示、微调、增强与推理技巧（通过创建和收集示范 demonstrations）。
  • 设计了一个编译器，优化任意 DSPy pipeline 以最大化给定指标。
  • 案例：几行 DSPy 就能表达并优化"数学应用题推理、多跳检索、复杂问答、控制 agent loop"的 pipeline；几分钟编译后超过标准 few-shot（通常 +25% / +65%）。

对你 SGRT 系统的含义

  1. 别再维护一长串手写提示：把"残差报告生成"拆成签名（输入：残差统计+阈值；输出：结论+依据），逻辑交给模块，格式由签名保证。
  2. 有指标就能自动调：你若有"判定准不准"的评测集（Week3 第 28 课），DSPy 优化器能替你调提示——省手工试错。
  3. 框架即抽象，要懂底层：DSPy 自动生成的提示要看懂（Week2 第 19 课 DSPy 签名的 prompt 形态），否则排障困难。

自测（先答再展开）

Q1. DSPy 三件套各回答什么问题？

展开答案

Signatures 签名：What（严格定义输入/输出契约）；Modules 模块：How（把签名与程序逻辑组合成可调用函数）；Optimizers 优化器：按数据与指标改进提示/权重。

Q2. DSPy 的"编译器"做什么？需要哪两样输入？

展开答案

编译器（optimizer）把任意 DSPy pipeline 优化到最大化某个指标，输入是 Data（数据）和 Metric（指标）。

Q3. DSPy 论文声称的核心收益是什么？给数字。

展开答案

几行 DSPy + 几分钟编译，让 GPT-3.5/llama2-13b-chat 自举出超过标准 few-shot 的 pipeline，通常 +25%（GPT-3.5）和 +65%（llama2-13b）以上。

Q4. 你的标定报告用 DSPy 改，最需要先准备什么？

展开答案

先准备 Data（一批示例/示范）和 Metric（判"报告对不对"的客观指标）。没有指标，优化器无从下手——呼应 Week1"评估先于建设"。
