通信：对话、handoff 与消息板

第 0057 课（Lecture08 第 3 课）· 来源：lecture08.pdf p30-49 · 来源文件夹：week5-10.19 · 本课成果：区分通信与协调（两个常被混淆的概念），掌握 handoff 与 agent-as-tool 的关键差别，认识 AutoGen/MetaGPT/A2A 三条通信路线

先给结论

先分清两个概念（p31）：
Communication 通信 = agent 之间怎么交换信息（谁收到什么、通过什么通道、什么格式）
Coordination 协调 = agent 之间怎么管理互相依赖的工作（谁负责什么、谁必须先做）

三种通信通道（p49）：
主对话线程（AutoGen）／handoff 与工具调用（OpenAI Agents SDK）／消息板（MetaGPT、Swarm、MoltBook）
标准化方向：Agent2Agent（A2A）协议

通信 vs 协调（p31）——这是本课第一个考点

Communication 通信Coordination 协调
问的是信息怎么交换互相依赖的工作怎么管理
具体问题谁收到哪条信息？通过什么通道？消息格式、协议、共享产物是什么？谁拥有哪个任务？什么必须先做？怎么分配依赖和解决冲突？
出错的典型表现信息没传到 / 传错格式 / 传给了不需要的人两个人做同一件事 / 顺序错了 / 冲突没人裁

为什么必须分清：它们解决不同的问题，修一个不能修另一个。通信做得好但协调没做，会出现"信息都传到了，但没人负责"；协调做得好但通信没做，会出现"分工清楚但拿不到需要的数据"。

一、主对话线程（AutoGen，p32-35）

AutoGen 的核心抽象：多 agent 通信 = 对话（conversations）。

所有 agent 在同一个对话线程里说话：

  [用户]    请分析这个 bug
  [Planner] 需要先看日志
  [Coder]   我去读日志... 拿到错误堆栈
  [Critic]  这个堆栈看起来像空指针
  [Planner] 那就按空指针修
  [Coder]   已修，测试通过

· 每个 agent 都能看到前面所有人说的话（共享上下文）
· 谁下一个说话由编排规则决定

课件的几种对话模式（p34）：

  • Sequential 顺序——agent 依次交接给下一个团队
  • Nested 嵌套——子 agent 直接跟管理者通信
  • Group Chat 群聊——组内共享上下文
  • Hierarchical Chat 层级——所有子 agent 向编排者汇报

AutoGen 现有实现：RoundRobinGroupChat、SelectorGroupChat、Swarm…

共享上下文的好处与代价：好处是没人缺信息；代价是上下文迅速膨胀——每个 agent 都要看所有人的话。

二、handoff vs agent-as-tool（p36-39）——本课最重要的一节

这两个概念很容易混，课件专门用 4 页对比。差别在于控制权归谁：

Handoff 交接Agent-as-Tool 把 agent 当工具
控制权转移——接收方变成活跃的，继续交互保留——调用方保持控制
上下文相关对话历史和任务细节跟着过去只发有界请求 + 选定上下文
返回接收方直接继续（可能直接面对用户）返回一个答案或产物，调用方继续
最适合专家应该直接与用户交互并负责后续步骤一个 agent 应该整合专家贡献并交付最终答复
【Handoff】
  用户 ──► 前台 agent ──"这个要专家处理"──► 专家 agent
                                              │
                                              ▼
                                          直接对用户说话
  → 控制权交出去了，前台不再参与

【Agent-as-Tool】
  用户 ──► 主 agent ──"帮我算一下"──► 专家 agent
              ▲                          │
              └────────返回结果──────────┘
  → 主 agent 用这个结果继续组织最终答复，控制权一直在它手里

工程含义：

  • Handoff 像是"转接电话"——转过去之后你就不管了。
  • Agent-as-tool 像是"打电话问同事"——问完继续自己的事。
  • 要保证最终回答的一致性，用 agent-as-tool；要让专家长期负责某个用户，用 handoff。

三、消息板（p40-44）

MetaGPT 的做法：agent 通过发布/订阅的方式在共享消息板上协作，而不是两两对话。

        ┌─────────────────────────┐
        │      消息板（共享）       │
        │  · 需求文档              │
        │  · 设计稿                │
        │  · 任务分配              │
        └───┬──────┬──────┬───────┘
            │      │      │
        产品经理  架构师  工程师
        （各自发布产物，订阅自己需要的）

课件还举了两个现象（p43-44）：HuggingFace 事故（METR 记录）和 MoltBook（"Social Memory"）。这两个例子说明：当 agent 在共享空间里互相发布信息时，会出现涌现行为——有好的，也有失控的。

四、A2A 协议（p45-48）

Agent2Agent (A2A) Protocol —— Google

定位：和 MCP 类似的"协议"，但 MCP 管 agent 与工具，A2A 管 agent 与 agent
内容：
  · Agent Cards —— 描述 agent 的能力（相当于名片）
  · agent 发现（discovery）
  · 消息传递
  · 产物（artifact）共享

课件的类比很清楚（p46）：A2A 是像 MCP 那样的协议，用来做 agent 之间的通信。

MCP  :  agent ←→ 工具/数据源      （L04 讲过）
A2A  :  agent ←→ agent            （本讲）
两者解决不同层的标准化问题，不冲突

通信通道总结（p49）

通道代表实现特点
主对话线程AutoGen共享上下文，简单直观，但上下文膨胀
handoff / 工具调用OpenAI Agents SDK明确控制权归属，可精确控制上下文传递
消息板MetaGPT、Swarm、MoltBook解耦、可异步、支持涌现协作，但难追踪
标准协议A2A跨组织/跨厂商的标准化发现与消息

SGRT 工程桥：你的排查助手该用哪种通信

【场景】主助手 + 三个专家（呼吸/机械/光学）

❌ 不要用主对话线程（AutoGen 式）
   原因：三个专家的原始数据（呼吸曲线、点云统计）会全部进共享上下文
        → 主助手上下文爆炸，而且大部分内容它不需要

✔ 用 Agent-as-Tool
   主助手 ──"查呼吸信号，重点看呼气末识别时刻"──► 呼吸专家
           ◄──"抖动 120ms，正常应 <50ms，怀疑基线漂移"──
   主助手拿到结论，继续自己的推理
   → 上下文只进两行结论，控制权始终在主助手
   → 最终报告由主助手统一组织，口径一致

✔ 什么时候用 Handoff
   如果呼吸问题确实需要专家深挖 20 轮
   → handoff 给呼吸专家，让它直接跟用户对话
   → 但要在交接时把"当前已排除的假设"一起传过去
   → 交接回来时要重新同步（否则主助手不知道发生了什么）

⚠️ 医疗场景的额外要求
   无论哪种通信，每次交互都要留痕：
   谁问的、问了什么、答了什么、依据什么数据
   → 这是合规要求，不是优化项

本课小结

通信 vs 协调：一个管信息怎么交换，一个管工作怎么分工——修一个不能修另一个。
三种通道：主对话线程（共享但膨胀）／handoff 与工具调用（控制权明确）／消息板（解耦但难追踪）。
关键对比：handoff 转移控制权；agent-as-tool 保留控制权。
标准：A2A 管 agent↔agent，MCP 管 agent↔工具。

自测（先答再展开）

Q1. 通信和协调的区别是什么？各举一个"做得好但另一个没做"的后果。

展开答案

通信是 agent 之间怎么交换信息（谁收到什么、什么通道、什么格式）；协调是怎么管理互相依赖的工作（谁负责什么、什么必须先做、冲突怎么解决）。通信好但协调没做：信息都传到了但没人负责、重复劳动。协调好但通信没做：分工清楚但拿不到需要的数据。

Q2. Handoff 和 agent-as-tool 的最本质区别是什么？什么时候各用哪个？

展开答案

本质区别是控制权归属：handoff 把控制权转移给接收方，接收方变成活跃的并继续交互（相关历史跟着走）；agent-as-tool 保留控制权在调用方，只发有界请求和选定上下文，收到结果后调用方继续。要让专家直接与用户交互并负责后续用 handoff；要让一个 agent 整合专家贡献交付一致答复用 agent-as-tool。

Q3. 主对话线程（AutoGen）方式最大的代价是什么？

展开答案

上下文膨胀。所有 agent 共享同一个对话线程，每个 agent 都要看所有人说的话，随着轮次增加上下文迅速增长，导致成本上升、延迟增加、且关键信息被淹没。同时每个 agent 都被迫接收与它任务无关的内容。

Q4. A2A 和 MCP 分别标准化什么？它们冲突吗？

展开答案

MCP 标准化 agent 与工具/数据源之间的交互（工具调用、上下文提供）；A2A 标准化 agent 与 agent 之间的通信（能力发现 Agent Cards、消息传递、产物共享）。两者解决不同层次的标准化问题，不冲突，可以同时使用。
