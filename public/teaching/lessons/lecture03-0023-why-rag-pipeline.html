为什么要 RAG：把"背下来"换成"现查现用"

第 23 课（Week3 第 1 课）· 来源：lecture03.pdf p10-21 + RAG 原始论文（Lewis et al., 2021）· 本课成果：讲清 RAG 的动机、retriever-reader 框架，以及 RAG 论文里 RAG-Sequence 与 RAG-Token 两种形态

先给结论

Week1 第 8 课讲了 RAG 的"概念三步"（检索→增强→生成），Week3 把它拆成工程细节。一句结论：别让模型把世界背进参数里，而是在回答时"即时给它相关资料"（just-in-time）。理由有三：知识可动态更新（改文档即改知识，不用重训）、可溯源（指出出处）、可降幻觉（答案有据可依）。

工程含义：RAG = 检索器 p(z|x) + 生成器 p(y|x,z) 的复合系统。你的 SGRT 资料（错误码表、处置 SOP、标定规范）天然适合 RAG——它们是"事实型、会更新、需要溯源"的内容。

为什么需要检索（p10-11）

课件开场例子：问"本周哪个答疑时段最不挤？"

  • 仅 LLM：答"周三下午吧，周中人少"——凭印象猜。
  • LLM + 检索：先检索到真实排队记录（"Tue 4pm 平均 14 人等；Thu 9am 只有 3 人"），再答"周四 9 点，约 3 人"。

动机（p11）：与其让模型"记住一切"，不如在需要时给它相关且有用的内容。检索的机制优势：动态——加/改文档很容易，比重新训练便宜几个数量级。

Retriever-Reader 框架（p12-13）

开放域问答的标准两段式：

输入: 文档集合 D = {D1 … DN} 与问题 Q        (N 可达百万级)
输出: 答案字符串 A
Retriever: f(D, Q) → P1 … PK     （先粗筛出 K 篇，K 常取 100）
Reader:    g(Q, {P1 … PK}) → A   （在 K 篇里读出答案）

早期 retriever 常用 TF-IDF 这类词频统计（DrQA, Chen et al. 2017, 83 万篇维基）。

RAG：把"检索"和"生成"焊在一起（p14-19）

RAG 论文的洞见：不分成两段，而是让 retriever 与 generator 联合（jointly）训练。两个部件（p16）：

部件作用论文里的具体实现
Retriever p(z|x)给定 query，返回 top-K 段落DPR：p(z|x) ∝ exp(d(z)ᵀ q(x))，d=BERT_d(z)、q=BERT_q(x)
Generator p(y|x,z)给定 query + 检索到的段落，逐 token 写答案BART（任意 encoder-decoder 都行），x 与 z 拼接后生成

答案的概率（p16）：p(y|x) ≈ Σ_{z∈top-K} p(z|x)·p(y|x,z)——用检索器给每篇段落的答案加权。

两种形态：RAG-Sequence vs RAG-Token（p16）

形态做法直觉
RAG-Sequence选一篇段落，用同一篇生成整段答案一篇资料答到底
RAG-Token每生成一个 token 都可重选段落每个词都能参考不同资料

训练（p17）

联合训练 retriever 与 generator，最小化负边际对数似然——即让"正确答案"在 top-K 段落加权后的概率尽量高。

效果（p20）

RAG 在 Natural Questions (NQ)、TriviaQA (TQA)、WebQuestions (WQ)、CuratedTrec (CT) 上，用 Exact Match 计分，超过纯参数 seq2seq 与任务专用的 retrieve-and-extract 架构；生成任务的语言更具体、多样、符合事实（论文摘要结论）。

对你 SGRT 系统的含义

  1. 哪些资料该 RAG 化：错误码表、故障处置 SOP、标定规范——事实型、需溯源、会修订。
  2. 不该 RAG 的：需要"背下来内化"的技能（如配准算法的取舍经验）更像后训练/微调的事，不是检索。
  3. 溯源是刚需：医疗场景答案必须能指出"依据哪份 SOP 哪一条"，这正是 RAG 相对纯生成的核心价值。

自测（先答再展开）

Q1. RAG 相对"让模型记住一切"的三个核心好处？

展开答案

(1) 知识可动态更新（改文档即改知识，不必重训）；(2) 可溯源（能指出出处）；(3) 降幻觉（答案有据可依）。

Q2. Retriever-Reader 框架里，K（top-K）是什么？

展开答案

Retriever 先粗筛出的段落数（常取 100），Reader 只在这 K 篇里找答案。K 是预先设定的。

Q3. RAG-Sequence 和 RAG-Token 的区别？

展开答案

RAG-Sequence：整段答案用同一篇检索段落生成；RAG-Token：每生成一个 token 都可重新选择段落，一个词也能参考不同资料。

Q4. 你的 SGRT 场景里，哪类资料最该做 RAG？为什么？

展开答案

错误码表、处置 SOP、标定规范这类事实型、需溯源、会修订的资料。因为 RAG 的三大好处（动态更新/溯源/降幻觉）正对口，且医疗场景要求答案可指出来源。
