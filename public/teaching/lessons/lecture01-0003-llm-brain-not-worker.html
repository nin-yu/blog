LLM 是大脑，不是执行者：三个天生缺口，三座桥

第 3 课（共 13 课）· 重建 v3 · 本课成果：能说出 LLM 作为“执行者”时的三个死穴，以及每个死穴对应哪一类补件 · 对应你 MISSION 第 3 条

先给结论

LLM 只会一件事：根据上下文生成文本。它天生缺三样——没手、没档案、没世界。补上它们的三座桥分别是：工具（Tools）、记忆（Memory）、环境/检索（Environment & Retrieval）。整套 agent 工程，本质就是给这颗大脑配齐手、档案和世界。

三个缺口 → 三座桥（本课核心表）

缺口具体表现补件（桥）学在
没手
（不能行动）		不能真去读文件、跑代码、查数据库、发请求；只能“说”它想做什么工具 Tools：把行动写成可调用的函数，让模型调用第 9 课
没档案
（不能长期记住）		上下文窗口装不下所有历史；关掉会话就忘光记忆 Memory：把经历/知识/技能存到外部再取回第 7 课
没世界
（没有实感/不知道实时事实）		知识冻结在训练时；会一本正经地幻觉；不知道你现场发生了什么环境 + 检索：读现场状态（Obs），用 RAG 接外部知识第 5、8 课

为什么会这样（原理，别跳）

  1. 模型的输出模态只有文本。它能生成“我建议重启服务”，但不会真的重启服务——除非你把“重启服务”包装成一个工具交给它调用。
  2. 模型是无状态的。每次调用都是全新的，除了你塞进上下文的东西，它什么都不记得。所谓“记住”，是系统帮你把历史重新拼回上下文。
  3. 模型的“知道”是统计拟合，不是事实查证。它容易幻觉（hallucination）：说得像真的、其实不对。唯一的解药是让它“以观察到的真实结果为准”——这正是第 5 课 loop 里 Obs 的作用，也是 RAG 的作用。
一句话记住三者关系：工具给行动力，记忆给连续性，环境给真实感。缺任何一样，agent 都只是“会聊天的模型”。

对照你熟悉的东西（工程桥）

把 LLM 想成一个只读过全部理论、但从没上过机的新操作工：

  • 他知道“标定板要摆正”，但手没接上设备——得给他工具：拍照、读残差、调参数（≠ 让他自己想象结果）。
  • 他记不住昨天那台机器的偏差——得给他档案（记忆）：历史标定记录、常见错误码。
  • 他不知道此刻病房里是什么情况——得给他世界（环境 / 检索）：实时日志、设备手册的即时检索。

你平时搭测试台时做的事（接接口、存档案、读实时状态），和这里要给 LLM 配的“三座桥”是同一件事。

自测

Q1. 为什么说“LLM 会幻觉，唯一解药是观察真实结果”？

展开答案

因为幻觉来自“凭统计拟合生成”，光靠在文本里自我反省治不了。只有当系统把真实的 Obs（工具返回、检索到的原文、现场状态）喂回去，模型才有“以事实为准”的锚点。这就是 ReAct 缓解幻觉、RAG 提升可信度的共同原理。

Q2. “模型是无状态的”这句，直接推出了哪座桥的必要性？

展开答案

记忆（Memory）。因为每次调用都是全新的，想让 agent 连着上一次继续干，必须由系统把历史/知识重新拼回上下文——这就是记忆的职责（第 7 课）。

Q3. 把“帮我重启服务”变成 agent 能做的一件事，缺的是哪座桥？

展开答案

工具（没手）。要有一个可调用的工具（如 restart_service()）供模型调用，模型负责“决定调用它 + 填参数”，真正的执行在系统侧。

Q4. 三座桥里，哪座最直接决定“这套系统答案可不可信”？为什么？

展开答案

环境 + 检索（世界）。因为它决定了 agent 的答案能不能“落在真实事实上”（现场状态、权威文档）。医疗场景尤其如此：没有证据链的自信回答是负债。
