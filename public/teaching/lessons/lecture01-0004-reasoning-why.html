推理为什么有用：ReAct、自洽性与反思

第 0004 课（Lecture01 第 4 课）· 来源：lecture01.pdf p33-43 · 来源文件夹：week1-9.23 · 本课成果：理解推理在 agent 里的定位（内部动作），掌握 ReAct 优于纯 Act 的原因、自洽性的聚合机制、Reflexion 与多 agent 辩论的作用

先给结论

课件给推理的定义（p33）：

对人：演绎、类比、规划等心智过程
对 LLM：模仿这些心智过程的中间生成内容
对 agent：更新 agent 自身状态的内部动作

最后一句是关键：推理不是"想一想"，它是 agent 的一种动作——只不过作用对象是它自己的状态。

一、推理是这个循环里缺的那一环（p34）

没有推理：
  观察 Obs ──────────────► 行动 Act
  "看到柜子和桌子"  →  "右转"
  
  问题：Observation to Action mapping could be hard
       直线映射，很多情况下根本映射不出来

有推理：
  观察 Obs → [推理] → 行动 Act
  "看到盐用完了" → "这道菜应该是咸的，盐没了要去找酱油，
                    酱油在右边柜子里" → "右转"

课件给了推理起作用的三条理由（p34）：

① Generalization 泛化
   不需要为每种情况预先写规则，推理能把情况映射到已有知识

② Alignment 对齐
   推理过程能表达"为什么要这么做"，让行为与意图一致
   （也让人能检查它是否理解对了）

③（隐含）可逐步观测
   推理写出来，你能看到它在哪一步想错了

二、ReAct 优于纯 Act（p36-37）

课件给了个很典型的例子（p35-36）：问"除了 Apple Remote，还有什么设备能控制 Apple Remote 程序"。

【只推理不行动（CoT）】
  Thought: 让我一步步想。Apple Remote 原本是为 Front Row 设计的…
  Answer:  iPod
  → 这个答案是错的（它靠记忆猜）

【推理 + 行动（ReAct）】
  Thought: 我应该查一下 Apple Remote 支持什么
  Act:     search("Apple Remote programs")
  Obs:     [搜索结果：支持 Front Row、iPod…]
  Thought: 搜索结果说明…
  Answer:  [基于真实结果的答案]
  → 踩在观察上，不是靠记忆猜

课件的两个结论（p37）：

· ReAct 稳定优于纯 Act
· 幻觉是 CoT 的严重问题，而 ReAct 能帮助缓解

第二条值得展开：CoT 的幻觉来自"纯靠内部记忆推导"；一旦引入观察，模型就有机会被真实数据纠正。

三、Self-Consistency：多次采样取多数（p38）

做法（p38 原文）：
  ① 用 CoT 提示语言模型
  ② 生成多样化的多条推理路径
  ③ 在最终答案集合中选择最一致的那个

图示：
  问题 ──┬──► 推理路径 1 ──► 答案 A
        ├──► 推理路径 2 ──► 答案 A
        ├──► 推理路径 3 ──► 答案 B
        └──► 推理路径 4 ──► 答案 A
                              ↓
                          投票：A 胜（3/4）

它的前提假设：正确答案有多条到达路径，错误答案往往分散。所以"多次独立推理后答案集中"就是可信信号。

代价：要跑 N 次（N 倍成本、N 倍延迟）
收益：显著提升准确率，尤其在数学/逻辑题上

→ 这就是 Lecture02 讲的"推理期扩展"的雏形

四、Reflexion：从失败中反思（p39-40）

Reflexion 的 agent 对任务反馈信号做语言层面的反思，然后维护自己的反思文本，以此引导更好的决策。 
机制（p40）：
  用自我反思，把冗长、失败的轨迹
  蒸馏成相关的经验
  → 这些经验在后续尝试中作为上下文使用

注意这里的表述和 Lecture06 的一致性：反思的价值在于"把失败轨迹压缩成可复用的经验"，而且它依赖"任务反馈信号"——不是纯自我评价。

五、多 agent 辩论（p41-43）

多 agent 辩论（Du et al. 2023）：
  多个 agent 各自给出答案和推理
  → 互相看对方的推理
  → 多轮辩论后收敛

为什么有用：
  不同 agent 的初始错误不同
  → 互相批评能暴露各自的漏洞
  → 类似 Self-Consistency，但多了"互相质询"这一步

课件还提到 Orchestrator 协调（p43，引 Magentic-One）：一个编排者协调多个 agent。这是 Lecture08 的内容，这里只是提了一句。

四种推理增强的对比

方法机制代价何时有用
ReAct推理与行动交替，踩在观察上多轮调用需要外部信息、易幻觉的任务
Self-Consistency多次采样投票N 倍成本有唯一正确答案、单次不稳
Reflexion失败后反思并记住多轮尝试有客观反馈、可重试
多 agent 辩论互相质询后收敛N 倍成本 + 协调判断类任务、单一视角易偏

SGRT 工程桥：你的排查助手该用哪一种

【首选 ReAct】
  排查的本质就是"不知道原因，必须边查边定方向"
  → 纯推理会编原因（幻觉）
  → ReAct 让每一步都踩在真实数据上

【Self-Consistency 慎用】
  每次排查跑 5 遍成本太高，且排查路径本来就不唯一
  → 但可以用在"关键判断点"：比如"这次是不是呼吸问题"
     让模型独立判断 3 次，答案不一致就提示"证据不足"

【Reflexion 可用，前提是有客观反馈】
  你的重投影 RMS、角点匹配率就是客观反馈
  → 第一次标定失败 → 反思"边缘误差大，可能畸变模型不够"
  → 第二次换 5 参数模型 → 成功

【多 agent 辩论：医疗场景不适合自动收敛】
  两个 agent 争"是床板还是呼吸"
  → 不要让它们自己投票决定
  → 把两边的证据一起上报给人

本课小结

推理的定位：agent 的"内部动作"，作用是更新自身状态。
为什么有用：Obs→Act 直线映射太难，推理插入这一环提供泛化、对齐、可观测。
ReAct：优于纯 Act，且能缓解 CoT 的幻觉（因为踩在观察上）。
Self-Consistency：多次采样投票，N 倍成本换准确率。
Reflexion / 辩论：反思靠客观反馈；辩论靠互相质询。

自测（先答再展开）

Q1. 课件对"推理"在 agent 里的定义是什么？为什么说它是"内部动作"？

展开答案

对人来说是演绎、类比、规划等心智过程；对 LLM 是模仿这些过程的中间生成；对 agent 是更新 agent 自身状态的内部动作。说是内部动作，因为它和"调用工具"一样是 agent 采取的一步，只不过作用对象是 agent 自己的状态而不是外部环境——它不改变世界，只改变 agent 接下来怎么行动。

Q2. 为什么 Obs→Act 的直接映射不够用？推理补上了什么？

展开答案

因为从观察到行动的直线映射在很多情况下根本映射不出来——"看到柜子和桌子"无法直接得出"右转"。推理补上三样：① 泛化，不需要为每种情况预写规则；② 对齐，能表达为什么这么做、让人能检查是否理解对了；③ 可观测，推理写出来能看到在哪一步想错了。

Q3. ReAct 为什么能缓解 CoT 的幻觉？

展开答案

因为 CoT 的幻觉源于纯靠内部记忆推导——模型在没有外部依据的情况下顺着语言模式编造。ReAct 引入了 Observation 环节，让模型的下一步踩在真实检索结果上，一旦想错了就有机会被真实数据纠正。所以"推理 + 行动交替"比"只有推理"更可靠。

Q4. Self-Consistency 的前提假设是什么？在你的场景里该用在哪里、不该用在哪里？

展开答案

前提假设：正确答案有多条到达路径而错误答案往往分散，所以多次独立推理后答案集中就是可信信号。你的场景不适合整段排查用（成本 5 倍且排查路径本就不唯一），但适合用在关键判断点——比如"这次是不是呼吸问题"让模型独立判断 3 次，不一致就说明证据不足，应提示需要更多数据。
