CS329Z 教学空间 · Lecture04 · Lesson 0025

RAG 的两个上限与 LLM 的四类做不到

第 0025 课（Lecture04 第 1 课）· 来源：lecture04.pdf p4-21 · 来源文件夹：week3-10.5 · 本课成果：理解 RAG 收尾时的两个上限，掌握 LLM 算不了/没见过/够不着三类短板，以及工具的严格定义

先给结论

RAG 收尾时课件给了两个"上限"（p5-9）：

上限一：模型用不了太多文档（p6-7）
　Oracle（只喂相关文档）准确率约 88.5%，闭卷只有 56%
　但 RAG 在 10-20 篇文档之后就不再涨了——继续喂没用

上限二：引用本身也可能是幻觉（p8-9）
　"这是 RAG 的独特价值：能给出引用"
　"但这些引用也是 LLM 生成的，所以引用也可能被幻觉"

这两条正好指向工具：模型最缺的不是更多文本，而是"能精确执行的动作"。

一、上限一：上下文装得下，也用不好（p5-7）

问题（p5）：为什么不把很多文档一起传给 LM？

数据（p6，Liu+ 2023）：
  Best Closed-Book（不给文档）      GPT-3.5-Turbo  ~56%
  Best Oracle（只给相关文档）        GPT-3.5-Turbo  ~88.5%
  → 差距 32 个百分点，说明"给对文档"确实有用

但（p7）：
  · 检索器召回率（黄线）慢慢爬到 90%
  · RAG 效果（其他线）在 10-20 篇文档后就饱和了
  → 继续增加文档数量，不再提升

课件的结论很直接：实践中 LM 用不了很多文档。

为什么？
  ① Lost in the middle（Lecture03 讲过）——中间的信息被忽略
  ② 无关文档造成干扰
  ③ 上下文越长，注意力越稀释（context rot）

→ 所以"多喂文档"这条路有天花板
→ 真正的解法不是"更多文本"，而是"更精确的手段"

二、上限二：引用也可能被幻觉（p8-9）

· RAG 的独特价值：能引用来源
· 但这些引用本身也是 LLM 生成的
· 所以引用也可能被幻觉……这种情况有多频繁？ 
课件给的两个观察（p8-9）：
  · 输出"易于阅读、看起来对评分者有用"（1-5 分高）
  · 但精确率和召回率都低（p9）
  → 也就是说：引用看起来很像真的，但经常是错的

这就是"看起来对"和"实际对"的差距
→ 在医疗/法律这类需要溯源场景，这是致命问题

三、LLM 的四类做不到（p17）——这是本课核心

课件用一张表把 LLM 的短板分成四类，每类都对应一种工具：

类别LLM 做不到的对应的工具
算不了大规模算术 / 多步逻辑演绎 / 精确可验证的运算计算器、代码解释器、符号求解器、验证器、确定性执行
没见过长尾事实 / 训练截止后的事件 / 私有数据Web 搜索、检索、实时 API、新闻流、内部语料 RAG
够不着非语言接口（API、数据库）/ 物理世界 / 实时状态（时间、价格、传感器）函数调用、MCP、浏览器、机器人、时钟、传感器、行情

课件还给了一个前置结论（p16）：任务复杂度上升时，LLM 的零样本准确率急剧下降——乘法位数增加、逻辑谜题房子数增加、DP 任务序列变长，都是同样的趋势。

四、工具的定义（p18）

LM 使用的工具，是一个"运行在 LM 外部"的计算机程序的函数接口；LM 生成函数调用和输入参数来使用它。
（Wang et al. 2024, arXiv:2403.15452） 
定义里三个关键词：

  "运行在 LM 外部"
    → 不是模型内部计算，是真的调外部程序
    → 所以能突破模型自身的能力边界

  "函数接口"
    → 有明确的输入输出契约
    → 不是自由文本

  "LM 生成调用和参数"
    → 谁决定调什么、传什么，是模型
    → 这是"工具使用"和"固定流水线"的区别

举个最简单的例子（p20）：
  Q: 17,423 × 892 = ?
  → 模型输出 calculate(17423 × 892)
  → 外部计算器返回 15,541,316
  → 模型说"等于 15,541,316"

SGRT 工程桥：你的场景里 LLM 的四类短板

【算不了】
  残差 RMS 计算、ICP 收敛判定、矩阵运算
  → 绝对不能让 LLM 心算
  → 必须调代码

【没见过】
  这台设备的历史记录、你们内部的标定规范
  → RAG 或直接查数据库

【够不着】
  当前设备状态（传感器）、实时日志
  → 工具调用（读接口）

【一个真实的风险案例】
  问："这次的重投影误差是多少？"
  ❌ LLM 看图像猜："大约 2.1mm"
  ✔ 调工具算："重投影 RMS = 2.34mm（基于 48 个角点）"

  → 前者听起来合理，但完全是编的
  → 这就是 RAG 收尾讲的"引用也可能幻觉"的同构问题

本课小结

RAG 两个上限：模型用不了太多文档（10-20 篇就饱和）／引用本身也可能被幻觉。
四类做不到：算不了（算术/多步演绎）／没见过（长尾/私有数据）／够不着（API/物理世界/实时状态）。
工具定义：运行在 LM 外部、有函数接口、由 LM 生成调用与参数。
关键：解法不是"更多文本"，是"更精确的手段"。

自测（先答再展开）

Q1. RAG 的两个上限是什么？为什么"多喂文档"解决不了第一个？

展开答案

上限一：模型用不了太多文档——RAG 效果在 10-20 篇文档后就饱和，继续增加不再提升（Oracle 88.5% vs 闭卷 56% 说明"给对文档"有用，但"给很多文档"没用）。上限二：引用本身也是 LLM 生成的，所以引用也可能被幻觉。多喂文档解决不了，因为原因是 lost in the middle、无关文档干扰、注意力稀释——这些是上下文变长的固有代价，不是"文档不够多"的问题。

Q2. LLM 的四类做不到分别是什么？各举一个对应的工具。

展开答案

① 算不了：大规模算术、多步逻辑演绎、精确可验证运算——对应计算器/代码解释器/验证器；② 没见过：长尾事实、训练截止后的事、私有数据——对应 Web 搜索/RAG/实时 API；③ 够不着：非语言接口（API/数据库）、物理世界、实时状态——对应函数调用/MCP/浏览器/传感器。课件把它们整理成"算不了/没见过/够不着"三类具体项加其他。

Q3. 工具定义里的"运行在 LM 外部"和"LM 生成调用与参数"这两个限定分别排除了什么？

展开答案

"运行在 LM 外部"排除了模型内部的计算——工具是真的调外部程序，所以能突破模型自身能力边界（如精确算术）。"LM 生成调用与参数"排除了固定流水线——是模型决定调什么工具、传什么参数，而不是代码预先写死调用顺序。这两条合起来才是"工具使用"，缺任一条都不算。

Q4. 为什么说"LLM 看图像猜重投影误差"和"引用幻觉"是同一类问题？

展开答案

因为两者都是"用生成能力伪装成事实获取"。引用幻觉是模型生成了一个看起来像真实出处的引用；猜重投影误差是模型生成了一个看起来合理的数值。共同点是：输出形式正确、语气自信，但内容没有真实依据，用户无法从表面判断真假。解决方法也相同——必须走真实的工具/数据通路，而不是让模型"说出"结果。
