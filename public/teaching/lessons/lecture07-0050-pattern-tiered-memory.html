模式二：分层记忆——MemGPT 与 MemoryOS 把内存/硬盘之分搬到 agent 上

第 0050 课（Lecture07 第 5 课）· 来源：lecture07.pdf p42-49 · 来源文件夹：week4-10.14 · 本课成果：理解分层记忆的核心机制（让模型自己管理记忆）、工作区/回忆/归档三层各自装什么，以及 MemoryOS 的三层扩展

先给结论

第二种模式（p42）：Tiered Memory Hierarchy——把长短期记忆分层组织。

MemGPT（p43-47）的核心洞察一句话：给 LLM 工具，让它自己管理自己的记忆。
它把操作系统那套搬了过来：Working Context（相当于内存）+ Recall Storage（可检索的近期历史）+ Archival Storage（长期归档）。

MemoryOS（p48-49）把层次细分：短期 / 中期 / 长期 + Persona（人格）记忆。

MemGPT 的核心洞察（p43）

Give the LLM tools to manage its own memory.（给 LLM 管理自己记忆的工具）

这句话的分量在于：它把"记忆管理"从外部程序逻辑变成了模型的工具调用。模型自己决定"这条要记住""这条该忘了""去检索一下之前的"。

【传统做法】上下文满了 → 程序按规则截断最老的 → 模型无感知
  问题：程序不知道什么重要，一刀切可能砍掉关键约束

【MemGPT】模型看到上下文快满了 → 自己调用工具把某段写入归档
        → 需要时再调用工具检索回来
  好处：模型知道什么重要
  代价：多消耗工具调用（延迟 + 成本），且依赖模型判断正确

三层结构（p45-46）

┌─────────────────────────────────────────────────┐
│  Working Context（工作上下文）                    │
│  相当于内存 / 寄存器                              │
│  · 当前对话 + 系统指令                            │
│  · 容量受限，就是模型的上下文窗口                  │
│  → 已在上下文里，不需要检索（p46 原话）           │
└───────────────┬─────────────────────────────────┘
                │ Write / Replace
                ▼
┌─────────────────────────────────────────────────┐
│  Recall Storage（回忆存储）                       │
│  相当于近期历史 / 可检索的对话缓存                 │
│  · 完整对话历史（超出工作窗口的部分）              │
│  → 需要时 search 检索回来                         │
└───────────────┬─────────────────────────────────┘
                │
                ▼
┌─────────────────────────────────────────────────┐
│  Archival Storage（归档存储）                     │
│  相当于硬盘                                       │
│  · 长期知识、文档、事实                            │
│  → 同样通过 search 检索                           │
└─────────────────────────────────────────────────┘

记忆操作（p45-46）：

  • Write——把内容写入工作上下文
  • Replace——替换工作上下文里的某段
  • Search——从 Recall / Archival 里检索

这个类比的边界（很重要）

"内存 vs 硬盘"很好用，但有两个地方不成立，必须知道：

操作系统的假设LLM 记忆的实际情况
内存换出/换入是无损的（字节原样搬运）写进记忆时是有损的——模型要"总结"才能存下
寻址是精确的（地址给定就取到）检索是相似度的——可能取到"看起来像"但不该用的东西

这两个差异决定了：分层记忆不是免费的扩容，而是"用检索精度换容量"。

MemoryOS：更细的分层（p48-49）

Short Term Memory（短期）
    → 当前会话的即时上下文
Medium Term Memory（中期）
    → 会话级别的摘要 / 主题
Long Term Memory（长期）
    → 跨会话的稳定知识
Persona Memory（人格记忆）
    → 用户是谁、偏好什么、怎么说话

多出来的两层都很有实际意义：

  • Medium：解决"整个会话讲完后,怎么快速回顾"——不是逐条翻历史，而是有主题摘要。
  • Persona：把"用户画像"独立出来，直接对应第 54 课讲的 Personalization 收益。

SGRT 工程桥：分层在医疗场景里的特殊约束

【MemGPT 的核心洞察在你的场景里要打折扣】

课件说：给 LLM 工具让它自己管记忆
你的场景：不能完全照搬
原因：  让模型自主决定"哪条记忆被替换/归档"，
       意味着关键信息可能在无审计的情况下被改写或移走。

【可借鉴的部分】
 分层本身：工作区（当前排查）/ 回忆区（本次会话历史）/ 归档区（历史案例）
 用工具暴露"检索"接口，但"写入/替换"由规则触发

【建议的分层设计】
  Working   : 当前排查的 10-20 步上下文
  Recall    : 本次排查的完整轨迹（只读，可检索）
  Archival  : 历史案例库（跨会话，带设备/版本标记）
  Persona   : 医疗设备不建议做"用户人格记忆"
              （不同技师用同一台机器，混淆身份有风险）

最后一条是主动取舍：课件把 Persona Memory 当特性，但多用户共用设备的场景下,人格记忆会带来身份混淆风险。不是课件说错了，是场景不同。

本课小结

模式二：分层组织长短期记忆，解决"上下文窗口装不下长期历史"。
MemGPT：给模型工具让它自管记忆（Write/Replace/Search）；三层=工作区/回忆/归档。
类比边界：换入换出有损、寻址靠相似度——分层是"用检索精度换容量"。
MemoryOS：短期/中期/长期/人格四层，中期=会话摘要，人格=用户画像。
医疗场景：分层可借鉴，但"让模型自主写入/替换"和"人格记忆"要谨慎。

自测（先答再展开）

Q1. MemGPT 的核心洞察是什么？它相对"程序按规则截断"有什么优势、什么代价？

展开答案

核心洞察是给 LLM 工具让它自己管理记忆。优势：模型知道什么重要，可以主动把关键内容写入归档、需要时检索回来，而不是被程序一刀切砍掉关键约束。代价：多消耗工具调用（延迟和成本增加），且效果依赖模型的判断是否正确。

Q2. "内存 vs 硬盘"这个类比在 LLM 记忆里，哪两处不成立？后果是什么？

展开答案

① 换入换出不是无损的——写进记忆时模型要做总结，信息会丢失；而 OS 的换页是字节原样搬运。② 寻址不是精确的——检索靠相似度，可能取到看起来像但不该用的内容；而 OS 给地址就取到。后果：分层记忆不是免费扩容，而是用检索精度换容量。

Q3. MemoryOS 相比 MemGPT 多加了哪两层？各解决什么问题？

展开答案

多了 Medium Term Memory（中期记忆，会话级别的主题摘要，解决整个会话讲完后怎么快速回顾）和 Persona Memory（人格记忆，记录用户是谁、偏好什么、怎么说话，直接支撑个性化收益）。

Q4. 为什么医疗设备场景不建议做"用户人格记忆"？

展开答案

因为多用户共用同一台设备——不同技师、不同班次都会用。人格记忆会把 A 的偏好套用到 B 的操作上，造成身份混淆和误判风险，而且难以审计这条偏好是谁的。
