CS329Z 教学空间 · Lesson 5

架构核心：一个 agent 由五大组件拼成，靠 loop 转起来

第 5 课（共 13 课）· 全课程的心脏课 · 本课成果：闭着眼画出这张图、复述四步循环，并在自己的 SGRT 场景里点名五个组件

先给结论

一个 agent = LLM Core（大脑）+ 规划推理（想）+ 记忆（记）+ 工具（手）+ 环境（世界），靠一个循环驱动：Obs（观察）→ Think（思考）→ Act（行动）→ 新的 Obs → … 直到完成。
后面 8 课，全都是在往这个环上插插件——先把这张图刻进脑子，后面就都是“往哪儿插、怎么插”的问题。

五个组件各自干什么（对号入座）

组件干什么你的 SGRT 场景里，它长什么样
LLM Core思考与生成语言的本体你选用的那个模型（如 deepseek-flash / qwen）
Planning & Reasoning“下一步干什么，才离目标更近”“先查错误码表，还是先看标定日志？”
Memory存住做过的事 / 学到的知识 / 练成的技能过去 30 次标定的结果档案、常见故障处置记录
Tools检索、跑代码、读写文件、查设备read_log()、查错误码表、算残差统计
Environment外部世界，提供观察、接受行动日志文件、设备数据库、操作工终端

读法：ReAct 论文里那串 Think/Act/Obs 的执行轨迹，就是这张架构图“跑起来”的样子。五大组件不是课件凭空分的，是从 ReAct 的记号直接翻译过来的——记住这一点，整门课就有了锚。

环怎么转（背这个四步）

  1. Obs：看一眼当前处境（环境返回的信息：日志新行、工具结果、用户消息）。
  2. Think：心里推演“接下来做什么才更接近目标”。
  3. Act：动手——调用工具 / 与环境交互 / 回复用户。
  4. 新的 Obs：看这一步造成了什么新局面，回到第 1 步。循环直到任务完成或触发终止条件。

为什么推理这一步不能省（课件 p33-34）：从 Obs 直接映射到 Act 往往很难。“盐用完了 → 该开右边的柜子拿酱油”是一步步推出来的，不是直接映射。推理带来两个好处：泛化（generalization）——新情况也能套；对齐（alignment）——行为可解释、可指挥。

三层抽象（课件 p55，调优时分层看）

  1. 系统层 The system：架构设计、组件怎么编排（本课 + 第 12 课）。
  2. 数据层 The data：训练示例、示范、上下文。
  3. 评估层 The evals：指标与评测——这一层定义“什么是好”（第 10 课）。

工程含义：出问题时先分清是“架构没设计对”还是“数据/指标没定对”。很多人一上来猛改架构，其实指标那层根本没定义清楚。

自测

Q1. 闭卷：默写五大组件 + 循环四步。（写在纸上再对）

展开答案

五组件：LLM Core / Planning & Reasoning / Memory / Tools / Environment。四步：Obs → Think → Act → 新 Obs。

Q2. “traces so far”对应哪个组件？这说明 Memory 的第一形态是什么？

展开答案

Memory。第一形态就是对话/执行轨迹本身（把走过的路留在上下文里）；等上下文装不下了，才需要外挂记忆（第 7 课）。

Q3. 推理对 agent 的两大好处（课件 p34）？

展开答案

泛化 generalization + 对齐 alignment。

Q4. 三层抽象里，“什么算好”由哪一层定义？这层没定好会怎样？

展开答案

评估层。指标没定好，系统层的调优就是盲调——你无法判断改动是变好还是变坏（第 10 课“评估先于建设”）。
