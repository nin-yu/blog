记忆三类：情景 / 语义 / 程序——区分点是“怎么写进去的”

第 7 课（共 13 课）· 重建 v3 · 本课成果：能用“写入方式”一刀切开三类记忆，并给每类配一个 SGRT 例子 · 对应第 3 课“没档案”那座桥

先给结论

上下文窗口装不下全部事件流；就算装得下，也很难聚焦相关事件——所以需要外部记忆。按内容分三类（借鉴人的长期记忆）：
情景记忆存经历、语义记忆存知识、程序记忆存技能。
最关键的区分点不是“存什么”，而是“怎么写进去”。

为什么要外挂记忆（原理）

模型是无状态的（第 3 课）。一个长任务会不断产生新事件，全塞进上下文有两个死结：① 装不下（超窗口被截断）；② 难聚焦（相关内容淹没在噪声里，注意力被稀释）。记忆系统的作用，就是“把该记的存到外面，需要时按相关性取回来”。

类型存什么写入方式（区分关键）读取方式代表

一句话分辨三者的写入口径：情景=原样记发生的事；语义=想一遍后记结论；程序=把“怎么做”固化成可执行技能。

三类怎么选（工程判断）

  1. 要“还原当时现场”（谁在什么时候做了什么、日志顺序）→ 情景记忆，追加式保真。
  2. 要“提炼规律/结论”（“这台机器连续三次标定都偏左 1mm，像是床板问题”）→ 语义记忆，先由 LLM 推理成知识再存。
  3. 要“下次自动会做”（“遇到这种错误码就走这套处置流程”）→ 程序记忆，固化成可复用的代码/技能。

对照你熟悉的东西（工程桥）

  • 情景记忆 ≈ 原始日志与时间戳轨迹（保真、可按时间回放）。
  • 语义记忆 ≈ 你写的故障复盘结论 / 偏差规律总结（人/模型加工后的知识）。
  • 程序记忆 ≈ 封装好的标定量测脚本、SOP 自动化（能直接调用的技能）。

你现在的做法（日志全存 + 手工复盘 + 脚本沉淀），本质就是同时在维护这三种记忆——只是还没有一个 agent 自动帮你写、自动帮你取。

自测

Q1. 三类记忆的区分点是什么？（提示：不是内容）

展开答案

写入方式。情景=追加式事件流；语义=LLM 推理后写入；程序=写成代码技能。内容会重叠，写入机制才是分类依据。

Q2. “上次标定时残差图右下角有一片异常高，后来确认是遮挡”——这更像哪类记忆？如果要变成“下次自动规避”呢？

展开答案

第一句是情景记忆（一次具体经历）。要“下次自动规避”，得把它加工成程序记忆——固化成一条可执行的检查/处置技能（LLM 先做语义提炼，再写成技能）。

Q3. 为什么“上下文窗口够大”并不能替代外挂记忆？

展开答案

因为除了容量，还有“聚焦”问题：相关事件会被大量无关内容稀释，注意力下降、成本飙升。外挂记忆是按相关性选择性取回，而非全量塞入。
