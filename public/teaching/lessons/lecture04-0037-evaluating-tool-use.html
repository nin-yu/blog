怎么衡量"工具调用"好不好：三大基准 + Pass^k

第 37 课（Lecture04 第 7 课）· 来源：lecture04.pdf p58-66 · 本课成果：认识 BFCL / ToolBench / τ-bench 三个基准各自测什么，理解 Pass^k 为什么要衡量"可靠性/一致性"而不只是"能过一次"

先给结论

工具调用要看三件事：选对工具+填对参数（BFCL）、在真实海量 API 上完成任务（ToolBench）、多轮对话中遵守规则并与用户协同（τ-bench）。

最关键的是 τ-bench 提出的 Pass^k：不是"试一次能过"，而是"连续 k 次都成功"的概率——衡量可靠性/一致性。这正对上你 SGRT 场景的诉求：排查助手要"每次都稳"，不是"偶尔灵"。

基准 1：BFCL（Berkeley Function-Calling Leaderboard, p58-60）

  • BFCL 是评估 LLM 调用函数（工具调用）能力的综合框架（Patil et al., 2025）。
  • 评估方式：基于 AST（抽象语法树）的离线评估 + 真实执行函数做真实世界评估。

p60 例子展示它测什么：

类别例子
Multiple Functions（多选一）"2+3=?" 给定 add/mult → 应调 add(a=2,b=3)
Parallel Functions（并行）"(2+3) 和 (4+5)? " → 应调 add(2,3), add(4,5)
Relevance Detection（该不该调）没有相关工具时应不调用

基准 2：ToolBench / ToolLLM（p61-62）

Qin et al., 2023：从 RapidAPI 爬 6000+ 真实 API，整理真实人类指令，覆盖 16k+ API，测"在真实海量 API 上完成多步任务"。

基准 3：τ-bench（p63-64）

Yao et al., 2024：Tool-Agent-User 交互基准——测多轮对话里工具、agent、用户三方的协同（不只是单次调用）。

核心贡献：Pass^k（p64）

Pass^k = P(连续 k 次采样试验都成功 | 已知 n 次里有 c 次成功)

对比  Pass@k = P(k 次里至少成功 1 次 | 已知 n 次里有 c 次成功)

区别（本课要点）：

  • Pass@k：至少成功一次就行——衡量"能力上限"。
  • Pass^k：连续 k 次都成功——衡量"可靠性/一致性"。
为什么重要：agent 要上线，不能看"偶尔能过一次"。p64 把"可靠且一致"显式做成指标——这就是你 Week1 第 10 课学的"能力≠可靠性"在工具调用上的具体化。

三个基准对照

基准测什么关键点
BFCL选对工具 + 填对参数（AST + 真实执行）多函数/并行/该不该调
ToolBench/ToolLLM16k 真实 API 上的多步任务规模化 + API 检索
τ-bench工具-agent-用户 多轮协同Pass^k 衡量可靠性/一致性

对你 SGRT 系统的含义

  1. 用 Pass^k 验收你的排查助手：同一故障问 5 次，要求"5 次都对"（或至少给出可复现的稳定行为），而不是"试一次成功就算过"。
  2. 建自己的小型 BFCL：拿 20–30 条真实指令 + 应调工具，测"选对工具+填对参数+该不该调"。
  3. 别忽略"该不该调"：BFCL 的 Relevance Detection 提醒——模型在不该用工具时硬调，也是失败（对应本讲最后的 failure modes）。

自测（先答再展开）

Q1. BFCL 用什么方式评估？测哪几类情形？

展开答案

AST 离线评估 + 真实执行函数。测多函数选择、并行调用、相关性检测（该不该调）等。

Q2. Pass^k 和 Pass@k 的关键区别？各衡量什么？

展开答案

Pass@k：k 次里至少成功一次（衡量能力上限）；Pass^k：连续 k 次都成功（衡量可靠性/一致性）。上线看 Pass^k。

Q3. 为什么"可靠性"对 agent 比"能不能过"更关键？

展开答案

因为 agent 要反复上线运行，偶尔成功无法依赖；连续多次稳定成功才可部署（呼应 Week1 能力≠可靠性）。τ-bench 把这一点显式量化成 Pass^k。

Q4. 你要验收 SGRT 排查助手，具体怎么测？

展开答案

建小型评测集（20–30 条真实指令+应调工具），测选工具/填参数/该不该调；并对同一故障重复 5 次看 Pass^5（要求稳定），而非只看单次成功。
