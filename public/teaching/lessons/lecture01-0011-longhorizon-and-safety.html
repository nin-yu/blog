长程与安全：任务跑成了，不代表它安全

第 11 课（共 13 课）· 重建 v3 · 本课成果：能说出长程任务的两个病根，并背出 87% 弹窗攻击，能据此列出你的护栏 · 上线前必读

先给结论

两条独立的问题：① 长程——上下文持续增长会“膨胀 + 漂移”，相关性下降；② 安全——任务成功 ≠ 安全合规。agent 可能“达成目标”却以破坏安全约束为代价。
安全评估必须单独设限、单独测，不能只看“任务完成率”。

一、长程上下文：为什么越跑越糊

agent 跑久了，上下文会持续增长，带来两个病根：

  1. 膨胀（grows）：历史越堆越多，最终超过窗口被截断。
  2. 漂移（drifts)：早期目标/约束在后面淹没，模型注意力被无关信息稀释，行为开始偏离。

解法方向：记忆分层（第 7 课）——把历史压缩/提炼，只把当前相关的取回上下文；以及定期“回读目标”，防止目标漂移。

二、安全：任务成功 ≠ 安全（课件 p63-70）

风险说明对你项目的含义
任务成功≠安全HarnessAudit Bench：agent“达成目标”可能靠违背安全约束实现评估要单列“安全合规”一栏，而非只看完成率
弹窗攻击恶意弹窗可把计算机 agent 带偏，攻击成功率 87%外部内容（网页/弹窗/工具返回）必须白名单过滤，不能直接当指令吃进去
隐私PrivacyLens：评估 LLM 行动中的隐私规范意识工具权限按最小必要开放；敏感数据脱敏/隔离
失调与谄媚misalignment & sycophancy：模型迎合用户而非坚持正确别让它“顺着你的猜测说”；关键结论要以证据为准
多智能体合谋多个 agent 协作可能互相配合越过约束（metr 事故调查）本课程暂不涉及多 agent；若未来引入，需设跨 agent 的硬约束
87% 这个数最该记：只要 agent 会读外部内容并据此行动，就默认它会被诱导。护栏要在系统侧，而不是指望模型“自己把持住”。

三、护栏清单（照这个设计你的系统）

  1. 工具默认只读：先给读日志/查手册这类无副作用工具；写操作单独审批。
  2. 白名单外部内容：网页/弹窗/第三方返回一律过滤，绝不直接当指令执行。
  3. 关键动作人审：涉及改变设备状态、下发参数的动作，必须人工确认。
  4. 安全合规单独评估：指标里明确一条“越权/违规动作次数 = 0”。
  5. 可审计**：所有工具调用、结论、出处留痕，事后可复盘（医疗场景硬要求）。

自测

Q1. 长程任务的两个病根是什么？对应第几课的解法？

展开答案

膨胀 + 漂移。对应第 7 课的记忆分层：压缩/提炼历史、按需取回、定期回读目标。

Q2. “87%”指的是什么？它对你的护栏设计意味着什么？

展开答案

恶意弹窗把计算机 agent 带偏、导致原任务完不成的攻击成功率 87%。含义：只要 agent 读外部内容并据此行动，就要默认会被诱导，必须对输入做白名单/过滤，把护栏放在系统侧。

Q3. 为什么“任务完成率”不能作为安全评估的唯一指标？

展开答案

因为任务可能以违背安全约束的方式被“完成”（HarnessAudit Bench 已证实）。必须把“安全合规”作为独立指标（如越权动作次数），否则会奖励危险行为。

Q4. 给你设想的 SGRT 故障排查助手列 2 条最关键的护栏。

展开答案

参考：① 工具全部只读（只查日志/手册/历史，不碰设备参数）；② 外部内容白名单 + 关键结论人审，且全程留痕可审计。
