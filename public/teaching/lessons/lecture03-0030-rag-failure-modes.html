RAG 会在哪儿翻车：三侧失败清单 + 工程对策

第 30 课（Week3 第 8 课 · 收官）· 来源：lecture03.pdf p63（Issues with RAG）· 本课成果：拿到一张"检索侧/阅读侧/循环侧"的失败清单，每一条配 SGRT 场景的检查点与对策，作为你自建 RAG 的验收表

先给结论

RAG 的失败不在一个地方——课件把它分成三侧：检索侧（召回天花板、索引过期、权限泄漏）、阅读侧（"迷失在中间"位置偏置、干扰、证据冲突）、循环侧（错误复合、无停止规则、提示注入）。

工程含义：每建一个 RAG，就照这张表逐条问"我会不会踩、怎么防"。它和 Week1 第 10-11 课的可靠性/安全直接接上——RAG 只是把那些风险换了个具体战场。

失败清单（p63 原文，逐条）

一、检索侧 Retrieval-side

失败含义SGRT 场景的检查点与对策
Recall ceiling 召回天花板检索不到=证据缺失，直接限制 agent 上限建 Hit@k/Recall@k 评测集；上混合检索；分块与上下文检索（24-25 课）
Stale index 索引过期文档改了但 embedding 没更新SOP/错误码表修订后要重建索引；加"文档时间戳 + 重建流程"
Permission leak 权限泄漏检索到并使用了"不该访问"的内容索引前做权限分区；检索时按用户/工位过滤（医疗数据红线）

二、阅读侧 Reader-side

失败含义SGRT 场景的检查点与对策
Lost in the middle 迷失在中间长上下文里中间位置的信息被忽略（位置偏置）把最关键证据放开头/结尾；别把 100 篇全塞进去，先重排
Distraction 干扰"像但无关"的内容分散注意力用重排（ColBERT/cross-encoder）提高精度，减少噪声块
Evidence conflict 证据冲突来源之间或与模型知识冲突给来源标注与优先级；冲突时以最新/权威规范为准并显式提示

三、循环侧 Loop-side（agentic RAG 特有）

失败含义SGRT 场景的检查点与对策
Compounding error 错误复合早期失误影响后续决策（呼应 Week1 第 10 课 0.95^10）关键节点设校验/人审；限制轮数
No stopping rule 无停止规则没有清晰的"何时算完成"条件设最大轮数/收敛判据（如 critic 分数达标即停）
Prompt injection 提示注入检索到的文本反过来操纵 agent外部内容白名单过滤；区分"数据"与"指令"（呼应 Week1 第 11 课 87% 弹窗攻击）

三侧一句话串起来

检索侧: 找不到 / 找的是旧的 / 找了不该看的        → 建评测 + 重建流程 + 权限分区
阅读侧: 塞太多忽略中间 / 被相似噪声带偏 / 证据打架  → 重排 + 位置策略 + 来源标注
循环侧: 错误滚雪球 / 不知道该停 / 被检索内容操纵     → 校验点 + 停止规则 + 注入防护

去建你的 RAG 前的验收清单

  1. 检索有没有天花板？先跑 Hit@k（第 28 课）——检索查不到，后面全白搭。
  2. 索引会不会过期？写下"文档改了就重建索引"的流程。
  3. 权限分不分区？哪些内容不能对该用户/工位检索。
  4. 证据放哪？最关键的放首尾，别全靠模型自己找。
  5. 有没有停止规则？最大轮数 + 收敛判据。
  6. 注入防不防？检索文本一律当"数据"，不当"指令"。

自测（先答再展开）

Q1. RAG 失败分哪三侧？各举一例。

展开答案

检索侧（召回天花板/索引过期/权限泄漏）、阅读侧（迷失在中间/干扰/证据冲突）、循环侧（错误复合/无停止规则/提示注入）。

Q2. "Lost in the middle"是什么？怎么缓解？

展开答案

长上下文里中间位置的信息容易被忽略（位置偏置）。缓解：把最关键证据放开头/结尾，并先重排减少塞入的噪声块。

Q3. 为什么"提示注入"在 RAG 里格外危险？

展开答案

因为检索回来的文本会直接进上下文，恶意/意外内容可反过来操纵 agent。对策：外部内容白名单过滤，严格区分"数据"与"指令"（呼应 87% 弹窗攻击）。

Q4. 你要给设备排查 RAG 定"停止规则"，可以是什么？

展开答案

例如：最大检索轮数（如 3 轮）+ 收敛判据（critic 相关性分达标即停），并在此之上加人审点。避免无限查下去（无停止规则）和错误滚雪球（错误复合）。
