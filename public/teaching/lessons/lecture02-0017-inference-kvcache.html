模型怎么吐字：Prefill / Decode 与 KV Cache 的账本

第 17 课（Week2 第 4 课）· 来源：lecture02.pdf p119-137（p133 KV Cache 为矢量图，可精确读）· 本课成果：说清"首字慢、后续快"的原因、KV Cache 为什么省算力又吃显存，以及投机解码怎么再提速

先给结论

模型回答分两阶段：Prefill（预填充）——把你给的整段提示一次性算完，计算密集、决定"首字延迟（TTFT）"；Decode（解码）——一个字一个字往外吐，每步只算一个新 token，显存带宽密集、决定"吐字速度（TPS）"。

KV Cache 是两阶段的桥梁：把已算过的 K、V 缓存下来，Decode 每步就不用重算历史——省算力，但缓存随对话变长而膨胀（吃显存）。投机解码再用一个小的草稿模型猜几个字、大模型一次校验，进一步提速。

Prefill 与 Decode（p120-135）

Prefill（预填充）Decode（解码）
输入整段提示（prompt）一次算每步 1 个新 token
瓶颈计算密集（GPU 算力）显存带宽密集（搬运 KV）
影响指标首字延迟 TTFT吞吐/吐字速度 TPS
并行度高（全序列并行）低（逐步串行）

p123 的"prefill+decode 并发请求"图说明：一个服务里 prefill 与 decode 交替，二者争抢资源——这解释了"为什么长提示会让所有人都变慢"。

Roofline 模型：为什么两阶段瓶颈不同（p122、p134-135）

Roofline（屋顶线）模型把任务分成"算力受限"和"带宽受限"两类：

  • Prefill：一次处理很多 token，矩阵大 → 算力受限（靠近屋顶的水平线）。
  • Decode：每次只 1 个 token，矩阵小 → 显存带宽受限（斜坡段）。
大白话：Prefill 是"搬很多砖，工人（算力）忙不过来"；Decode 是"每次只搬一块砖，但仓库门（带宽）太窄"。优化手段因此不同——前者堆算力/批处理，后者靠 KV Cache、投机解码。

KV Cache（p133，矢量图）

Decode 每生成一个字，若都把历史重算一遍，代价巨大。KV Cache 的做法：缓存每个已处理 token 的 K、V，新 token 只算自己的 Q 去和缓存的 K、V 交互。

已生成: The class was about …
缓存:   [K][V] for "The" "class" "was" "about"   ← 全部留存，不再重算
新 token: 只需算自己的 Q → 拼上缓存 → 出下一个词
  • 省的是算力：避免 O(n²) 的重复计算。
  • 吃的是显存：缓存大小 ≈ 层数 × 头数 × 维度 × 序列长度。对话越长越占显存。
  • 关键约束：缓存跟"前缀"绑定——所以 p168-169 才强调"顺序追加，避免让 KV Cache 失效"（一旦前缀改动，缓存全作废重算）。

投机解码 Speculative Decoding（p136-137）

思路：用一个便宜的小"草稿模型"先猜出后面几个 token，再让大模型一次并行校验这几个猜测（对的接受、错的回退）。

草稿模型: Once upon a time → 猜 "there" "upon" "a"
大模型:   一次前向校验 4 个位置 → 接受前缀，回退错误处
收益: 某些领域（可预测性强）每一步能一次吐多个字，速度提升明显

p137 配套论文点明：有些领域更可预测，猜中率高，提速更显著。

对你 SGRT 系统的含义

  1. 首字延迟 vs 吐字速度要分开测：你的日志排查 agent，若提示很长（大段日志），TTFT 会明显拉长——这就是要"检索压缩上下文"的直接原因（少喂 → 少 prefill）。
  2. KV Cache 是显存预算：想本地常驻跑一个长对话助手，得按会话长度估显存，不能只看模型参数大小。
  3. 不要频繁改动前缀：系统提示/工具定义放在固定位置、按顺序追加，才能让 KV Cache 命中、避免重算。

自测（先答再展开）

Q1. Prefill 和 Decode 的瓶颈分别是什么？各影响哪个指标？

展开答案

Prefill 是算力受限，影响首字延迟 TTFT；Decode 是显存带宽受限，影响吞吐/吐字速度 TPS。

Q2. KV Cache 省了什么、代价是什么？

展开答案

省了算力（避免每步重算历史的 K、V）；代价是显存——缓存随对话长度线性增长（层数×头数×维度×长度），长对话吃显存。

Q3. 为什么"尽量让前缀保持不变、顺序追加"很重要？

展开答案

KV Cache 与前缀 token 序列绑定；一旦前缀改动（中间插入、重排），缓存失效需重算，白付一次 prefill 成本。所以系统提示/工具定义放固定位置、顺序追加。

Q4. 投机解码怎么提速？什么样的领域收益更大？

展开答案

用小草稿模型先猜几个 token，大模型一次并行校验（接受对的、回退错的），从而一步吐多个字。可预测性强的领域（如格式化输出、固定代码模板）猜中率高，收益更大。
