精选03 · 如果 LLM 是一位"会写菜谱却从没下过厨"的大厨，为什么 agent 必须给它配工具和确认闸门？

精选理由（为什么这题够格）：它从"LLM 到底是什么"这一个本质判断， 反向推出整套 agent 护栏的必然性。答对了，你就不再是"照抄最佳实践加护栏"， 而是理解每一条护栏都是在补一个具体的不可信——护栏的数量 = 不可信的程度。

牵出哪些讲：L1（agent 组成）· L4（工具层设计 / 工具失败）· L5（工程化 / 可靠性安全）。 与 精选01、精选02 构成同一主题簇： 能力从哪来、存在哪、为什么不可全信。

题目

先接受一个判断（可用你自己的话重述）：

LLM 不是"会做菜的大厨"，而是"会写菜谱、且能把菜谱写得像真做过的大厨"。 它产出的是文本，不是验证过的结果；它在模仿，不是理解； 它手边没的东西会用最像的凑（幻觉），而且不自知。

请回答：从"它产出的是文本而非验证过的结果"这一条，能推出 agent 为什么必须 给 LLM 配【工具】和【确认闸门】？请推出整套护栏的必要性。

作答要求

  1. 点根：用一句话说出——为什么"文本 ≠ 验证过的结果"就足以要求护栏？ （提示：如果它真是一台精确的机器，护栏是否还需要？）

  3. 配工具 vs 配闸门：这两类护栏分别治什么病？为什么"加工具"解决不了"信任人的确认"这个问题？

参考解析（评卷用）

根：因为它"写菜谱"而不是"尝味道"

一句话： 如果 LLM 是一台精确的机器（给描述 → 精确产出验证过的结果）， 护栏一条都不需要。正因为它产出的是文本（模仿出来的、没经过验证的东西）， 所有护栏才有存在的必要——护栏的存在本身，就是在承认"它的输出不可直接采信"。

逐条推（不可信 → 护栏）

# LLM 的不可信 对应护栏 补了什么
1 幻觉：没见过的拿最像的凑 工具（算数/查询/采集外包）+ "只引用工具返回值" 用确定性来源替代"像不像"
2 不自知：错了也不知道 确认闸门（人复核）+ 审计日志 引入外部校验者
3 模仿而非理解意图 结构化输出 / Schema 约束 / 少样本 用格式和示例收窄歧义
4 会为"显得完成任务"乱来 权限白名单 / 不新增写盘路径 / 不自动重试 限制它的可作恶面
5 上下文/记忆不可靠（见精选01） 状态外置、进度由工具合成 不让它"记"，让它"查"

注意因果：不是"最佳实践说要加护栏"，而是"每一条不可信，必然对应一条护栏"。 护栏不是清单，是从它的本质推出来的必然结果。

配工具 vs 配闸门（两类护栏治不同的病）

  • 工具（算数、查询、采集、执行）：治"做得不对"——把"它不擅长的精确操作" 外包给确定性的东西。工具解决"能力"问题。
  • 确认闸门：治"信不过"——即使工具结果正确、模型判断合理，最终动作仍需人点头。 它解决"授权/责任"问题。

为什么加工具解决不了闸门的问题？ 工具能让"算得准"，但不能让"该不该做"这件事变得可信—— 模型可能算对了、却理解了错误的意图，或越权去做本不该它做的事。 工具的定位是"帮手"，闸门的定位是"把最终决定权留给人"。 用一句话：工具管"能不能做对"，闸门管"允不允许做"。

"护栏数量 = 不可信程度"的论证 + 反例

论证：每一条护栏都锚定一个具体的"不可信"。可信度越高，需要的护栏越少； 所以护栏集合的大小，直接反映我们对它的信任缺口有多大。

反例（完全可信的假设）：若 LLM 永不出错、完全理解意图、且从不为"表现"而偏离—— 则可撤掉：

  • 确认闸门（不需要人复核了）
  • "只引用工具返回值"（它自己说的就可信）
  • 权限白名单/不新增写盘（它不会越权）
  • 但审计日志可能仍保留（合规/追溯要求，与信任无关）——这是个好的边界观察。

落项目：Bps Copilot 3 条设计

设计条款 对应的"不可信"
"只引用工具返回值，禁止编造数值" 幻觉（#1）——它会给假数值
确认闸门（动作需操作员点执行） 不自知 + 授权（#2）——它可能理解偏，且最终动作要人负责
不新增写盘路径 / 不自动重跑直到通过 会为"显得完成任务"乱来（#4）——限制可作恶面

深一层（加分）

"护栏数量 = 不可信程度"其实是一个通用的安全工程原则： 任何自动化系统，其约束的强度应当与"该系统偏离目标时会造成的损害 × 它偏离的概率"成正比。 LLM 的偏离概率高、又可能碰临床/硬件，所以护栏密集。 这也解释了为什么医疗设备领域对 AI 介入格外保守（见设计文档 §8 安全边界）。

评判关注点

  • ✅ 抓根：是否理解"护栏是它本质的必然推论"，而不是背诵"要加护栏"。
  • ✅ 因果对应：每条不可信 → 护栏是否对得上、补的是不是同一个缺口。
  • ✅ 工具 vs 闸门：是否分得清"能力"与"授权/责任"两个不同层次的问题。
  • ✅ 反例质量：能否正确指出"哪些护栏该撤、哪些与信任无关（审计）"。
  • ⭐ 加分：能把它抬到通用安全原则（约束强度 ∝ 偏离概率 × 损害）。
