精选05 · 为什么"走迷宫"比"一条路走到底"更接近 agent 的真相？——CoT 与 ReAct 的本质差别

精选理由（为什么这题够格）：它用一个人人都会的日常经验（走迷宫）， 把"纯推理 CoT"和"边想边做 ReAct"的差别讲到骨子里，还顺带解释了 "为什么 agent 要设最大步数上限"。答对了，你就理解了第 5 课 loop 里 为什么必须有 Observation 这个环节——这是整个 agent 架构的承重墙之一。

牵出哪些讲：L1（reasoning methods / agent loop）· L4（工具调用 = 那只探路的脚）· L5（可靠性与保护逻辑）。对应课件 p35-36 苹果遥控器案例。 主题簇补充：前三/四题讲"能力/记忆/可信度/推理从哪来"，本题讲"推理为什么要闭环"。

题目

先看一个经典案例（课件 p35-36，苹果遥控器）：

问：除了 Apple Remote 本身，还有哪些设备能控制它当初被设计来控制的那款程序（Front Row）？

纯推理（CoT）：Apple Remote → Apple TV → iPhone/iPad/iPod Touch。 答错：漏了真答案"键盘功能键"。它一次推到底，中间没去查。

ReAct（边想边做）：Thought→搜→Obs→改搜→Obs→再搜→Obs， 最后从 Observation 里查出"Front Row 由 Apple Remote 或键盘功能键控制"。 答对：每一步都被事实校正。

请回答：

  1. 点本质：用"走迷宫"这个比喻，说明 CoT 和 ReAct 的本质差别。 （提示：一个是在"走"迷宫，一个是在"回忆"迷宫。）
  2. 指关键部件：这个比喻里，哪一步对应 ReAct 的 Observation？ 如果没有它，ReAct 会退化成什么？
  3. 说清 CoT 的死穴：为什么 CoT 会"走到底却走错、还不自知"？ "都走右边"这个说法对应 CoT 的什么毛病？
  4. 连到工程：走迷宫"每步探路"很好，但为什么还必须设"最多走 N 步"？ 这对应 agent 的哪个设计？
  5. 抽象一层：用控制论的词概括 CoT 与 ReAct 的差别。

参考解析（评卷用）

1. 本质差别

  • CoT = 凭脑子里的地图，一次性画出路线。 模型没在"走"迷宫，它在回忆迷宫—— 照着印象（"苹果的控制器就是 iPhone"）直接规划一条路，走到底。
  • ReAct = 摸黑走，每到一个岔路口就伸脚探一下（Observation）。 探到的是硬事实，不是印象； 哪怕印象里没这条路，脚一探也知道。

一句话：CoT 是一口气推完不回头，ReAct 是走一步看一步。

2. 关键部件 = Observation（"探路的脚"）

  • 那个"伸脚探一下"就是 Observation。
  • 没有它，ReAct 退化成 CoT（只剩干想，无外部校正）。
  • 有它，模型每圈都被事实拽住一次，幻觉没机会连成链——这就是课件的结论 "Obs 把推理拽回事实"。

3. CoT 的死穴

  • CoT 走的每一步靠的是**"印象规则"（想当然），不是"现实反馈"**。
  • "都走右边" = 用一条死规则贯穿全程（遇到岔路就按同一个习惯走）， 而不是在每个岔路口重新判断。苹果案例里，那条死规则就是"苹果的控制器 = iPhone"。
  • 结果：印象里缺一条岔路（键盘功能键），就漏了真答案，而且它自己不知道—— 因为从头到尾没有任何回头验证。

4. 为什么要限步数

  • "每步探路"虽好，但岔路无限多、或原地打转时会鬼打墙：无限走、烧 token、出不来。
  • 对应 agent 的 最大轮次上限（MaxToolRounds） 与 "无进展即停" 保护逻辑。
  • 呼应精选04 的坏处"陷入循环、烧 token"——这是同一条。

5. 控制论概括

CoT 是开环推理（假设模型对了，直接输出）；ReAct 是闭环推理 （每步看反馈、纠偏）。Observation 就是传感器读数。

→ 工程桥：ReAct ≈ 迭代配准/闭环控制（每算一步看残差），CoT ≈ 开环一口气算到底。

深一层（加分）

  • 这个比喻把 ReAct 的机制（逐步观测）、优势（踩在事实上）、 代价（慢、要步数上限）一网打尽。
  • 本质：为推理加一个"现实接口"（Observation），把开环变成闭环。 这与精选03"工具是事实来源"、精选04"推理是能力放大器不是事实来源"完全同构—— 三题合起来回答：推理要靠什么才不出错 → 靠事实接口（工具/Observation）。

评判关注点

  • ✅ 抓住本质：是否说清"CoT 在回忆迷宫、ReAct 在走迷宫"。
  • ✅ 指认关键部件：是否明确 Observation = 探路的脚，且知道没它会退化成 CoT。
  • ✅ CoT 死穴：是否理解"死规则贯穿 + 无回头验证 → 走错不自知"。
  • ✅ 限步数：是否连到 MaxToolRounds / 无进展即停，并知其为防鬼打墙。
  • ✅ 抽象：能否用"开环 vs 闭环"概括。
  • ⭐ 加分：把它连回精选03/04 的"事实接口"主线。
