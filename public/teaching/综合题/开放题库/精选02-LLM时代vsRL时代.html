精选02 · "LLM 时代"相比"RL 时代"，给 agent 带来的最本质变化是什么？

精选理由（为什么这题够格）：它逼你把"agent 是什么"这个问题想到底。 大多数人能背出"现在都用大模型当大脑"，但说不出这个转变在内核上意味着什么。 答对了，你不只是知道一个时代更替，而是理解了 "策略"这种能力到底存在哪里—— 这决定了你怎么设计 agent、什么该训练、什么该用 prompt。

牵出哪些讲：L1（agent 定义与历史）· L2（训练三阶段 / in-context learning）· L5（工程化：提示即代码）。 与 精选01 互补：精选01 讲"记忆从哪来"，本题讲"能力/策略从哪来"。

题目

先对齐两个词（不是时间先后，是范式）：

  • RL 时代（传统强化学习）：智能体通过与环境交互、试错、拿奖励来学习策略。 策略存在参数里，靠训练获得。代表：DQN、AlphaGo。
  • LLM 时代：智能体不重新训练了，直接用预训练大模型当大脑， 靠 prompt / 上下文 / 工具来定义行为。代表：ReAct、function calling。

请回答：从 RL 时代到 LLM 时代，给 agent 带来的最本质变化是什么？

作答要求

  1. 一句话点本质：用一句话说出最本质的那个变化（提示：问自己——agent 的"策略/能力"存在哪里？怎么获得？）。
  2. 列连锁效应：至少从 4 个维度对比两个时代（如：能力怎么获得、换任务成本、泛化、交互原语、人的介入方式、门槛）。
  3. 精确补刀：LLM 时代是不是就"淘汰"了 RL？如果不是，RL 退到了什么位置？ （这问考察你是否能把话说准，而不是喊口号。）
  4. 落到你的项目：以 Mono-BPS BPS Copilot 为例，说明它的"策略"存在哪、 如果要改它的行为（比如新增一个排查步骤）你改什么、需不需要训练。

参考解析（评卷用）

根：策略的载体变了 —— 从"参数"到"上下文"

最本质的一句话：

agent 的"策略/能力"，从"必须训练进参数"，变成了"可以用自然语言在运行时指定"。 RL 时代要造一个会做某事的 agent，你得训练它； LLM 时代，你用嘴描述就行。

更凝练：RL 时代"学会" = 更新参数；LLM 时代"学会" = 改上下文。 这把 agent 的定义权，从"训练工程师"手里，交给了"写提示的人"。

连锁效应（≥4 维度）

维度 RL 时代 LLM 时代
能力怎么获得 训练/试错/奖励信号塑造权重 描述/组合/少样本示例（in-context learning）
策略载体 参数（训练出来的权重） 上下文（prompt + 工具 + 记忆）
换任务成本 重新训练（贵、慢、要数据） 改 prompt（秒级、零训练）
泛化 绑定训练分布，分布外失效 开箱即用的世界知识 + 泛化
交互原语 动作空间（离散/连续向量） 自然语言 + 工具调用
人的介入 设计奖励函数（难、易错） 写提示词（直观）
门槛 要 ML 团队 会说话就能定义任务

精确补刀：RL 没被淘汰，它"换了位置"

严格说，LLM 时代没有抛弃 RL（DeepSeek-R1 正是用 RL 训出来的，见"聊天模式为何能推理"）:

  • 训练期仍然用 RL，甚至越来越依赖它来提升推理能力；
  • 但 agent 的构建期，策略不再靠训练，而是靠上下文装配。

准确表述：RL 从"agent 的构造手段"退位成了"模型的训练手段"。 RL 没消失，是它的位置变了——从"现场塑形策略"退到"离线增强底座能力"。

（答成"LLM 淘汰了 RL"是典型的不精确，本题会扣分。）

落到项目：Bps Copilot 的策略在哪

  • 策略载体：
    • 行为的"骨架"在 Shared/agent/knowledge.cpp 的 system prompt（安全规则、SOP 索引、 "每步先调 calib_progress"这类约束）；
    • 可用动作范围在 ToolRegistry（工具清单 + JSON Schema）；
    • 具体怎么做由 LLM 运行时判断（每一圈循环决定调哪个工具）。 —— 三处没有一处在训练参数里。
  • 要改行为（如新增一个排查步骤）：改 system prompt 措辞 / 加一条知识条目 / 加一个工具， 不训练、不重新编译模型。这就是 LLM 时代"改 prompt = 改策略"的直接体现。
  • 要不要训练：不要。模型（DeepSeek）是现成底座，Copilot 的设计全在"上下文 + 工具"这一层。

深一层（加分）

本质是：能力获取的接口，从"梯度"变成了"上下文"。

  • RL 时代：一切能力必须先被参数化（奖励塑形 → 权重），带来三个硬约束： 任务一变要重训、奖励函数难设计、样本效率低。
  • LLM 时代：能力预训练好了（世界知识+语言+推理），agent 只需在推理时把任务描述清楚。 换任务 = 换 prompt；人的意图 = 直接写自然语言（跳过奖励设计）；少样本即学新任务。

评判关注点

  • ✅ 抓根：是否说出"策略载体从参数→上下文 / 能力获取从梯度→上下文"这个根本。
  • ✅ 对比成体系：维度是否覆盖"获得方式 / 换任务成本 / 泛化 / 人的介入"，而不是零散罗列。
  • ✅ 精确性：是否能把 RL 的"位置变化"说准（训练手段 vs 构造手段），而不是喊"淘汰 RL"。
  • ✅ 落地：能否指出 Bps Copilot 的策略在 prompt+工具+运行时判断，且改它不需要训练。
  • ⭐ 加分：能点出"能力获取接口从梯度变上下文"这个本质命名。
