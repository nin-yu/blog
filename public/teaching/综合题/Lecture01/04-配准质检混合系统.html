题 4 · 配准质检混合系统（★★）

考点："固定管线 + 少量 LLM 判断点"的混合设计（Lesson 12）。这是工程上最常用、也最容易被做错的结构。 场景：胸腹表面配准（Point-to-Plane ICP + 呼吸门控 end-exhalation + Tukey 权重 + ROI 裁剪）每次跑完，你想要一个"自动质检 + 异常定位"模块。

题目

  1. 拆分：这条质检链路里，哪些环节必须保持固定管线（代码定步骤、可复现），哪些适合交给 LLM 判断？逐环节说理由。（至少列出：数值阈值检查、残差分布/空间模式分析、历史对比、报告生成）
  2. 为什么数值判定不能交给 LLM？ 从可靠性（一致性/鲁棒性）角度论证。
  3. LLM 判断点具体怎么设计：给它什么输入（上下文里放什么）、要它输出什么（结构化结论？建议？）、输出给谁用（人/下游程序）？
  4. RAG 在这里怎么用：哪些历史资料进知识库，检索什么，喂给谁？
  5. 失败模式设计：如果 LLM 判断点给出的分析明显不可靠（比如同输入两次结论不同），系统怎么办？（考察：可预期失败 + 降级路径）

我的作答

1. 拆分

2. 数值判定为什么不给 LLM

3. LLM 判断点设计

4. RAG 用法

5. 失败降级

评判关注点（评卷时用）

  • 1：阈值/数值对比=固定管线（可复现、可审计）；空间模式解读/建议生成=LLM。分层清晰。
  • 2：应答出一致性（同输入不同输出会毁掉验收）与鲁棒性（措辞扰动改变判定=质量事故），且数值判定有客观对错，LLM 引入不必要方差。
  • 3：输入=结构化摘要（指标数值+残差统计+异常区域描述），输出=受控格式（如 JSON 标签+建议文本），用途=给人看/触发人工复核，而不是直接控制设备。
  • 4：历史案例（残差超标当时的原因+处置）进库；检索当前模式相似案例；喂给 LLM 当参考证据。
  • 5：降级路径：LLM 不可信时回退到纯阈值结果+标记"需人工分析"，系统整体不失效。
