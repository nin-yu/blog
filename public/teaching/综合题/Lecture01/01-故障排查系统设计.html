题 1 · 故障排查助手全设计（主考题 ★★★）

场景：SGRT 设备报错进来了（比如"标定板识别失败"或"ICP 残差 RMS 连续超标"），你要做一个智能助手：拿到报错 → 判断是相机 / 标定板 / 床板哪个环节的问题 → 给出排查建议。 这是你 MISSION 里"故障排查"环节的最小版本。逐题作答，每题都要写为什么。

题目

  1. 你选 workflow 还是 agent？为什么？（用四问法逐问过一遍）
  2. 你要给它配哪几样东西（工具 / RAG 检索 / 记忆）？各自干什么？请具体到你的 SGRT 场景——相机、标定板 ±30°、ICP 配准、床板 QA 2mm/1°，能用上的都用上。
  3. 它的 agent loop（Obs→Think→Act→Obs）在这个任务里怎么转一圈？举一个具体报错从进来到出建议的完整例子（每个 Obs/Think/Act 都写一句）。
  4. 怎么保证它"可靠"？ 分别设计一致性、鲁棒性、可预期失败三个测试（给出具体测试集和通过标准）。
  5. 怎么保证它"安全"？ 哪些必须人拍板？哪些工具必须只读/沙箱？怎么防第三方内容带偏（提示：87%）？
  6. 一句话：上线前你最担心它在哪里出错？

评判关注点（评卷时用）

  • 第 1 题：路径未知 + 每步观察决定下一步 → 应判 agent（ReAct 式）；若答 workflow，看理由是否成立。
  • 第 2 题：有没有落地的组件（只读日志工具 / 错误码表 RAG / 历史工单记忆），还是空名词。
  • 第 3 题：Obs/Think/Act 是否真的交替且后步踩在前步观察上（ReAct 的本质）。
  • 第 4 题：三个测试是否可执行（固定测试集、跑 N 次、扰动、必败输入），不是"多测几遍"。
  • 第 5 题：只读权限、人审点、白名单三件套有没有配齐；患者数据红线有没有提。
