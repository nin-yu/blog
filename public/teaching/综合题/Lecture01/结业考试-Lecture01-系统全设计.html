题目

给一个 SGRT 场景，做一次完整设计。

场景：你要为"每日标定 QA"做一个智能助手——每天采集标定数据后，它要判断本次标定通过 / 不通过，不通过时给出可能原因，并生成一份可归档的中文报告。

请逐步作答，每步写为什么：

  1. 范式判定：这个任务该用 workflow 还是 agent？用四问法（步骤已知？中间结果可检查？失败代价？怎么算对？）逐问过一遍再下结论。
  2. 组件选配：给它配哪几样东西（LLM Core / 工具 / 记忆 / 检索）？各自在最容易出错的环节干什么？
  3. loop 或管线：把它画出来——如果是 workflow，画固定管线；如果是 agent，写清 Obs→Think→Act 怎么转一环。
  4. 评估：怎么算"对"？给出一个你能实际跑起来的指标（准确率/一致性/耗时）。
  5. 可靠性：设计一致性、鲁棒性、可预期失败三个测试（具体测试集 + 通过标准）。
  6. 安全：哪些必须人拍板？哪些工具必须只读？第三方内容（如导入的 Excel 备注）怎么防带偏？

评判关注点（评卷时用）

  • 第 1 题：流程固定、结果可枚举（通过/不通过）、指标现成（2mm/1°）→ workflow 正确；若判 agent，看理由是否成立（如"异常归因路径未知"可作为部分 agent 化的理由）。
  • 第 2 题：是否落在具体件上（读标定日志的工具、错误码表 RAG、历史标定档案记忆），而非空名词；LLM 判断点是否收敛到"摘要成报告"这类少量点。
  • 第 3 题：管线是否清晰、每步输入输出明确；若 agent 化，Obs/Think/Act 是否真的交替。
  • 第 4 题：指标是否可执行（如"100 次标定对照人工判定的准确率""同一输入跑 5 次的通过判定一致率"）。
  • 第 5 题：三个测试是否具体（固定测试集 / 跑 N 次 / 加扰动 / 必败输入），不是"多测几遍"。
  • 第 6 题：人审点、只读工具、外部内容白名单三件套；是否提到患者/医院数据红线。
